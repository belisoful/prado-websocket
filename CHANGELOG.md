# Changelog

All notable changes to `belisoful/prado-websocket` are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- Pub/sub messaging for browsers: the `prado.pubsub.v1` subprotocol, served by `TWebSocketPubSubHandler` (`Prado\IO\Socket\WebSocket\PubSub\`). Clients `subscribe`, `unsubscribe`, `publish`, `send` (direct message), `call` (application RPC) and `ping` over JSON text frames, routed through the cluster. The handler raises `onSubscribe`, `onPublish`, `onSend` and `onCall` with a `TWebSocketPubSubEventParameter`; client publish and send are denied unless `AllowClientPublish`/`AllowClientSend` or an event handler allows them. `MaxSubscriptions` (default 64), `MaxFrameSize` (default 65536 bytes; a larger request is refused with `limit` before it is decoded, and the `welcome` announces it as `maxFrame`) and `Heartbeat` (default 25 s) configure it; `publish()`, `sendTo()`, `broadcast()`, `subscribe()` and `encodeMessage()` serve application code. A request is refused with a `TWebSocketPubSubException` reply code.
- `prado-pubsub.js`, the dependency-free browser client (`TWebSocketPubSubHandler::getClientScriptPath()`): promise-based requests with timeouts, reconnection with exponential backoff and jitter, re-subscription, an offline queue, and a heartbeat that detects a stalled connection.
- `IWebSocketClusterAware`. `TWebSocketModule` gives its cluster to a cluster-aware handler and re-raises the pub/sub request events as its own `onSubscribe`, `onPublish`, `onSend` and `onCall`.
- Error codes: `websocket_pubsub_frame_too_large`, `websocket_pubsub_frame_malformed`, `websocket_pubsub_type_unknown`, `websocket_pubsub_channel_invalid`, `websocket_pubsub_field_required`, `websocket_pubsub_subscription_limit`, `websocket_pubsub_forbidden`, `websocket_pubsub_client_unknown`, `websocket_pubsub_method_unknown`, `websocket_pubsub_internal_error`.
- Error codes: `websocket_module_event_loop_invalid`, `websocket_module_event_loop_class_invalid`.
- `IWebSocketBufferedBackplane`: an optional backplane interface (`getWriteSources()`, `flushSource()`) through which the server drains a backplane's queued socket output when the socket becomes writable. `TMeshBackplane` implements it; `IWebSocketBackplane` is unchanged.
- `TPermessageDeflateExtension::isAvailable()` and `TPermessageDeflateNegotiator::isAvailable()` report whether ext-zlib is loaded. Error codes: `websocket_permessage_deflate_zlib_missing`, `websocket_permessage_deflate_deflate_failed`.
- Playwright specs for the browser client against the pub/sub handler (`tests/playwright/pubsub.spec.js`); `ws-server.php` serves pub/sub with `WS_PUBSUB=1`.
- `examples/chat`: a multi-room chat on `TWebSocketPubSubHandler` and `prado-pubsub.js`, with history, whispers and reconnection. It runs as a standalone server or as a PRADO application (`websocket/serve`), and `tests/playwright/chat-example.spec.js` covers both versions.
- `TWebSocketServer::setShutdownTimeout()` (default 2 s) and the `TWebSocketModule` `ShutdownTimeout` property; `TWebSocketServer::shutdownSessions()`, which a host that drives `serveOnce()` calls itself; `TWebSocketServer::handleLoopError()`, the reactor `ErrorHandler` `serve()` installs.
- `IWebSocketEndpointLimits`: an optional `IWebSocketEndpoint` interface through which an internal endpoint declares the `MaxMessageSize` and `MaxSendBufferBytes` of the connections it accepts. `TMeshBackplane` implements it with `LinkMaxMessageSize` and `LinkMaxSendBufferBytes`.
- `TWebSocketConnection::getReadTimedOut()`; `TWebSocketException::getDecodedMessages()`/`setDecodedMessages()`; `TWebSocketFrame::MAX_CLOSE_REASON_LENGTH`; `THttp2WebSocketProtocol::MAX_DEFERRED_BYTES`.
- `IWebSocketPolledBackplane` (`getHasBacklog()`), implemented by `TRedisBackplane` and `TFileBackplane`; `TWebSocketCluster::getHasBacklog()`; `DrainLimit` on both (default 10000; 0 means no count limit); `TRedisBackplane::DRAIN_TIME` and `REAP_ATTEMPTS`.
- `TMeshBackplane::SslContext`, `PeerPattern`, `UNVERIFIED_MESSAGE_SIZE` and `ANNOUNCE_INTERVAL`; `TWebSocketEnvelope::NODE_SYNC`.
- `TWebSocketPubSubHandler::encodeRelay()` and `scanRequestId()` (protected).
- Error codes: `websocket_read_failed`, `websocket_http_field_invalid`, `websocket_close_reason_too_long`, `websocket_close_reason_not_utf8`, `websocket_http2_input_overflow`, `websocket_backplane_mesh_peer_pattern_invalid`, `websocket_pubsub_number_out_of_range`.
- Tests: `pubsub-client.spec.js` (Node-side tests of `prado-pubsub.js` against a scripted socket), `ChatExampleHandlerTest`, `TMeshBackplaneServerTest` (mesh dials through a real server, TLS included); `ws-server.php` takes `WS_MAX_MESSAGE` and `WS_MAX_FRAME`.

### Security
- A connection that this side closed delivers nothing more to its handler. Before, a client refused in `onOpen` (closed with 4401, as the pub/sub docs recommend) still had every request it sent until its own Close run: pipelined behind the handshake, or sent after the server's Close. `TWebSocketServer` (HTTP/1.1 and HTTP/2) and the synchronous `handleConnection()` loop stop dispatching once `TWebSocketConnection::getIsCloseInitiator()` is true; messages before a Close the peer sent are still delivered. `TWebSocketPubSubHandler` ignores requests on such a connection too.
- `TMeshBackplane`: the accepting node answers a peer's challenge only after verifying that peer, so the dialer answers first. Before, an attacker without the secret could replay one captured plaintext handshake to two nodes and have each sign the other's nonce, passing both challenges and receiving presence and cluster traffic.
- `TWebSocketPubSubHandler` refuses a frame over `MaxFrameSize` before decoding it. A 10 MiB frame under the server's default `MaxMessageSize` took about 600 MiB to decode and could end the daemon. `prado-pubsub.js` refuses such a request itself, with `limit`, and rejects one it cannot serialize with `bad_request` instead of throwing.
- HTTP/2 is held to the limits HTTP/1.1 has. A transport is a pending handshake until its first WebSocket stream opens, so a peer that sends `PRI ` or only the preface is dropped at `HandshakeTimeout`; an idle transport is sent an HTTP/2 PING and reaped when it goes unanswered, and one that carries no stream is ended, under `IdleTimeout`; a stream that never completes its close is reset at `CloseTimeout`. Before, an HTTP/2 transport escaped all three.
- `MaxConnections` counts each HTTP/2 stream as it opens: a stream past the limit is refused with 503, and each session advertises the limit as SETTINGS_MAX_CONCURRENT_STREAMS (`THttp2WebSocketProtocol::setAdmission()`, `setMaxConcurrentStreams()`). Before, one transport could open any number of WebSockets.
- `MaxSendBufferBytes` bounds an HTTP/2 stream: the limit counts the bytes the stream holds while its peer withholds flow-control window (`TWebSocketConnection::getQueuedLength()`), and the server pulls no more HTTP/2 output for a transport holding `HTTP2_OUTPUT_HIGH_WATER` bytes. Before, a peer granting no window let a stream queue without limit.
- A peer that resets while being shed at `MaxConnections` no longer keeps its slot. The 503 write failed and skipped the close, so each such peer raised the load for good until every client was refused.
- A large frame received in small reads costs time linear in its size; each read copied the whole buffered frame, so a peer trickling a frame near `MaxMessageSize` could occupy the event loop. Bytes received after the peer's Close are discarded rather than buffered without limit.
- The HTTP/1.1 upgrade parser refuses with 400 a request head with a second `Host`, whitespace before a field's colon, or an obs-fold line, and an upgrade carrying `Transfer-Encoding` or a non-zero `Content-Length`, whose body would otherwise be read as WebSocket frames (RFC 7230 §3.2.4, §5.4). `TWebSocketHandshake::parseHttpMessage()` reports these as `malformed`.
- `TWebSocketHandshake::buildClientRequest()`, `buildServerResponse()` and `buildRejection()` refuse a host, path, key, header name or value, or reason phrase containing CR, LF or NUL (`websocket_http_field_invalid`), so a caller-supplied value cannot inject a header.
- `HandshakeTimeout` bounds a silent peer on a blocking stream: `readHandshake()` gives the stream the time remaining as its read timeout before each read. Before, a peer that sent one line held the synchronous path for `default_socket_timeout` and then escaped `serveConnection()` with a `RuntimeException`.
- An HTTP/2 session holds at most `THttp2WebSocketProtocol::MAX_DEFERRED_BYTES` (1 MiB) of input received while a handler waits on the event loop; a peer that floods control frames past it ends the session. Before, flow control bounded only DATA, so held PING or SETTINGS frames grew without limit.
- `TMeshBackplane`: an accepted peer that has not answered its challenge may send messages of at most `UNVERIFIED_MESSAGE_SIZE` (4096) bytes until it is verified. Before, each of up to `MaxPendingPeers` links held open with a replayed handshake could buffer a full `MaxMessageSize` (about 640 MiB in all).
- `TMeshBackplane::PeerPattern`: a PCRE an announced peer URI must match before a node dials it; seeds are always dialed. The default (`''`) dials any announced `tcp://`, `tls://` or `ssl://` URI, as before. Error code: `websocket_backplane_mesh_peer_pattern_invalid`.
- `TFileBackplane::open()` logs a warning when a parent directory of the spool is owned by another user, or is writable by group or others without the sticky bit.
- `TWebSocketPubSubHandler` honors `Allowed` on `onCall`: a handler that calls `setAllowed(false)` denies the call with `forbidden`.
- `examples/chat`: subscribing to a room requires joining it; a nickname is held by one client at a time, ignoring case, and whispers are addressed by client id, so an impostor cannot receive them (a `chat.join` token takes a nickname back after a reconnect); `?ws=` accepts only a URL on the page's own host; at most `MAX_ROOMS` rooms keep state, the least recently used empty room making way.

### Fixed
- A mesh peer message larger than the socket buffer no longer waits for the next send on that link: the link flushes on every tick, and the server watches links with queued output for writability. Before, a large broadcast could stall for minutes, and steady traffic overflowed the link and dropped the peer.
- When a node crashes, every node drops its clients, not only the one that reaped it: Redis sends a `NODE_DOWN` (the reserved envelope type, now handled by `TWebSocketCluster`) to every node, and the File backplane logs a presence drop per reaped client.
- A node that restarts under a static `NodeId`, or reconnects to Redis after an outage, replaces its presence on every node, so clients of its previous incarnation and clients that left during the outage no longer linger. The mesh detects a restart from a per-process incarnation in each node announce; nodes running 1.1.0 ignore it, so a rolling upgrade converges once every node is upgraded.
- A Redis node reaped while it was stalled (a GC pause, a suspended VM) rejoins on its next heartbeat, declaring its channel interest and presence again instead of staying unreachable.
- The File backplane's reaper drops the decoded client id, so the clients of a node whose id needs URL encoding (such as `host:q`) are removed; and a File node that stalled past twice `PresenceTtl` writes and announces its live clients again instead of leaving an empty presence file.
- An HTTP/2 session that nghttp2 has finished with, after a peer's connection error (a malformed frame) or a completed GOAWAY, is closed once its GOAWAY is sent. Before, the transport and its streams were held open.
- Socket tests no longer block on a reply the server has not yet sent: they pump the server until the bytes arrive, so a slow tick passes and a real failure fails within seconds. This was the intermittent 60 s failure on PHP 8.5.
- A throwing handler `onClose` on an HTTP/2 stream no longer skips the cluster unregister of that stream, or of the transport's other streams when it ends.
- A handler exception fails only its own connection, as on the synchronous path: `onError` is raised and the WebSocket closes with 1011, or with the exception's close code for a `TWebSocketException`. Before, over HTTP/2 it dropped every WebSocket on the transport without `onError`, and over HTTP/1.1 through `serveOnce()` it dropped the transport with no Close, no `onError`, and lost the rest of the read. A throwing `onOpen` on an HTTP/2 stream resets that stream only.
- `TWebSocketServer::serve()` shuts down gracefully: when it ends, every live WebSocket (HTTP/2 streams included) is sent a Close with 1001 and given `ShutdownTimeout` to answer, then every session ends through `onClose` and the cluster unregister, and every transport is closed. Before, `onClose` never ran on shutdown, and a standalone server leaked the transports.
- An exception from an application timer or a fiber the loop resumes no longer ends `serve()`: it is logged at ERROR and the loop carries on. A reactor that already has an `ErrorHandler` keeps it. `serve()` restores the prior `TAsync` loop and detaches when `cluster->open()` or `cluster->close()` throws.
- A handler that waits on the main fiber no longer has its HTTP/1.1 session's later messages dispatched re-entrantly, out of order, or after its `onClose`: the transport stays unread until the handler returns. During such a wait the cluster is ticked on every reactor tick, so a readable cluster source no longer spins the loop.
- A write to or read from a reset peer throws `websocket_write_failed` / `websocket_read_failed` and marks the connection closed under PRADO's error handler too, which raises the EPIPE/ECONNRESET notice as a `TPhpErrorException` that the `\RuntimeException` catches missed; the send queue no longer grows. The server ends an HTTP/2 session on such a write failure, and the handshake fails with a `TWebSocketException`.
- Messages a read completed before a malformed frame are delivered before the connection fails, over HTTP/1.1, HTTP/2 and mesh links. Before, they were discarded with the read.
- `TWebSocketConnection::receive()`/`receiveFrame()` buffer a frame that arrives in pieces and return null until it is complete. Before, a partial frame on a non-blocking stream threw `websocket_frame_incomplete`, losing its bytes and misparsing the rest.
- A blocking read that reaches the stream's read timeout returns null and keeps the connection and any partial frame (`getReadTimedOut()`). The synchronous `handleConnection()` loop pings an idle peer at each timeout and closes it with 1001 when a second timeout passes with no Pong or message, instead of failing it with 1011 after `default_socket_timeout`.
- The server echoes an offered `server_max_window_bits` even when it is 15, as RFC 7692 §7.1.2.1 requires; a strict client failed the handshake. The client fails a response that omits a `server_max_window_bits` it offered.
- `close()` with a reason over 123 bytes, a reason that is not UTF-8, or an unsendable code throws before changing state; before, the connection was left closing with nothing sent. `TWebSocketFrame::close()` checks the reason's length and encoding.
- `isHostAllowed()` (`AllowedHosts`) compares the host without regard to case, as the Origin check does.
- `THttp2WebSocketProtocol::send()` returns, in the same call, the output produced by input held while the session was busy. Input held across a `receive()` that threw is fed before the next call's bytes. The synchronous HTTP/2 `serve()` raises `onClose` for live streams when a transport read or write throws.
- The accepting end of a mesh link no longer inherits the client `MaxMessageSize`, so a binary broadcast near the client limit, larger once base64-encoded in an envelope, no longer drops the peer: both ends apply `TMeshBackplane::LinkMaxMessageSize`.
- A `tls://` or `ssl://` mesh dial no longer blocks the event loop: the node connects over TCP asynchronously and runs the TLS handshake without blocking, under `Timeout`, with the URI's host as the peer name. A dial that is still connecting is one of `getWriteSources()`, so writability completes it instead of the next cluster tick. A hostname still resolves synchronously.
- Mesh presence converges after a transient silence in a partial mesh: a node that hears from a node it holds no liveness for floods a `NODE_SYNC` naming it, and that node re-announces its presence, at most once per `ANNOUNCE_INTERVAL` (1 s). Before, the clients of a node behind an intermediary were lost for good. Nodes running 1.1.0 relay the request and do not answer it.
- The Redis inbox drain reads and trims in one `MULTI` transaction, and a reap is one `WATCH`ed transaction covering the registry, channel interest, inbox, presence and the `NODE_DOWN` to every node; a heartbeat writes its key before rejoining the registry. A node that resumes during a peer's reap now either aborts the reap or rejoins after it, and a producer's trim can no longer delete unread entries. Each inbox push sets the inbox to expire after three `NodeTtl`, so an inbox recreated after a reap is removed.
- Redis and File read inbound traffic in bounded ticks (`DrainLimit`) and report a backlog, and the server ticks the cluster again at once. Before, Redis drained at most 1000 envelopes per poll, about one per second when idle, and sustained churn filled the inbox to `InboxLimit`, whose trim discards the oldest entries, presence drops included.
- A File node no longer reaps its own live clients' presence files after a stall longer than twice `PresenceTtl`, when the refresh `touch()` left a stale cached mtime.
- `TWebSocketCluster::unregister()` visits only the disconnecting client's channels; before, every disconnect scanned every channel on the node. `sendToClient()` sends nothing to a client the presence mirror does not hold.
- `TWebSocketEnvelope::decode()` requires the type and the origin to be strings and the type to be a well-formed name (an unknown well-formed type is still relayed). An envelope without an id gets one derived from its bytes, so copies relayed over several paths are recognized as duplicates.
- Docblocks: `IWebSocketBackplane` and `TNullBackplane` no longer call the Redis backplane "pub/sub", and the coordinator, not the backplane, adds the node id to presence metadata.
- A `TWebSocketException` thrown while a pub/sub request runs, from an `onCall` handler or from a write to another client whose send buffer overflowed, is logged and answered `internal`; the requester keeps its connection. Only a failure to write the requester's own reply ends it.
- Pub/sub relays data as sent: a publish or send carries the JSON text of the request's `data` unless an event handler replaced it. Before, `{}` arrived as `[]`, `{"0":"x","1":"y"}` as `["x","y"]`, and integers past 2^63 lost precision. A number outside the float range (`1e400`) is answered `bad_request`, not `internal` with an ERROR logged.
- A pub/sub frame that cannot be decoded (a lone UTF-16 surrogate, nesting past the depth limit), or one over `MaxFrameSize`, is answered with its `id`, found by a bounded scan of the frame's top-level members, so the browser client's request settles at once instead of waiting out `requestTimeout`.
- `prado-pubsub.js`: a subscribe that times out is unsubscribed, and the subscribe of a channel left while it was in flight is not resent after a reconnect; requests held while connecting are sent after the `welcome`, so `maxFrame` applies to them; the client loads with CommonJS `require()` in Node (a `package.json` beside it declares `"type": "commonjs"`).

### Changed
- PHP 8.2 is the minimum (`"php": ">=8.2.0"`), following PRADO 4.4, which dropped PHP 8.1 (pradosoft/prado#1290). CI and PHPStan cover PHP 8.2 to 8.5.
- CI runs on `ubuntu-26.04`. `belisoful/prado-http2` 1.2 needs libnghttp2 1.60.0 or later, and Ubuntu 24.04 ships 1.59.0, so the HTTP/2 tests were skipped there on PHP 8.2 and 8.3 and crashed PHP 8.4 and 8.5. The README lists the libnghttp2 requirement.
- The development dependency on `belisoful/prado-http2` is `^1.3`, the release CI builds against.
- `THttp2WebSocketProtocol` holds bytes received while its HTTP/2 session is busy and feeds them, in order, once the outer `receive()` or `send()` returns; a `send()` made during another `send()` returns `''`. `prado-http2` 1.3 refuses to re-enter a session's nghttp2 call (`http2_session_busy`), and a handler that waits on the event loop outside a fiber of its own ticks the reactor from inside that call. Before, the server's next read of that transport threw and ended the whole HTTP/2 connection.
- Playwright is `@playwright/test` 1.62.1, as PRADO pins; 1.60.0 cannot install browsers on Ubuntu 26.04.
- Development tools are pinned to PRADO's exact versions: `friendsofphp/php-cs-fixer` 3.95.27 and `phpstan/phpstan` 2.3.3. PHPStan runs at level 4 with `treatPhpDocTypesAsCertain: false`, as PRADO does, and phpunit reports every error and deprecation (`error_reporting=-1`). The unused `phpdocumentor/shim` is removed.
- permessage-deflate needs ext-zlib up front: without it, constructing `TPermessageDeflateNegotiator` or `TPermessageDeflateExtension` throws `websocket_permessage_deflate_zlib_missing`, so a server or module configured for compression fails at configuration rather than with a fatal `Error` after negotiation. A `deflate_add()` failure throws `websocket_permessage_deflate_deflate_failed`.
- CI runs php-cs-fixer and phpstan from `vendor/bin` at the pinned versions and adds a PHP 8.4 leg against the Packagist `belisoful/prado-http2` release. The Autobahn job builds the same prado-http2 revision as the unit jobs, pins its Docker image by digest, has a 30-minute timeout, loads ffi, and fails a report with fewer than 500 cases. Workflows have read-only permissions and cancel superseded runs.
- `.gitattributes` keeps tests, CI and tool configs out of the Composer dist; `agents/` and `examples/` ship.
- `.nvmrc` pins Node 24, as PRADO does.
- README marks pub/sub and the PHP 8.2 minimum as 1.2.0 (unreleased), and its `tryDecode()` example uses the returned `frame` and `length`.
- Runs on PRADO's event loop API (pradosoft/prado#1377). `TSocketReactor` is now an `IEventLoop`: `TWebSocketServer` schedules its handshake and close deadlines with `delay()`, its idle scan with `repeat()`, and cancels them with `cancel()`, so timer identifiers are strings. A deadline timer that fires before the server's clock reaches the deadline re-arms itself, and a server that moves to another reactor with `setReactor()` re-arms its pending handshake and close deadlines there.
- `TWebSocketServer` measures its handshake, close and idle timeouts on a monotonic clock, as PRADO's timers now do (pradosoft/prado#1440), so a wall-clock step neither expires nor postpones them. The server uses `TMonotonicClockAwareTrait` (`getMonotonicClock()`, `setMonotonicClock()`) and shares the clock with the reactor it creates. Before, the timeouts read the server's wall clock.
- `config/errorMessages.txt` entries are ICU MessageFormat patterns, as PRADO now formats them with `MessageFormatter` (pradosoft/prado#1437). A quoted placeholder is written `''{0}''`; the single-quoted `'{0}'` the file used rendered a literal `{0}` in every message that named a value. A unit test checks that each entry is a valid pattern that renders every argument, that the file defines exactly the codes `src/` throws, and that each message is a sentence.
- `websocket_frame_incomplete` and `websocket_pubsub_subscription_limit` use ICU `plural`, so a count of one reads "1 byte" and "1 subscription", and a count of 1000 or more is grouped ("16,384 bytes").
- `TWebSocketPubSubException` implements PRADO's `IUserException` (pradosoft/prado#1373): its message is the text of the `error` frame sent to the client, so `TErrorHandler` also shows it to the visitor in Normal and Performance mode.
- `TWebSocketServer::serve()` makes its reactor the `TAsync` loop while it serves and restores the prior loop on exit, so a fiber that a handler starts with `TAsync::run()` resumes. Before, such a fiber waited on the default Revolt loop, which nothing ran, and never resumed. `TWebSocketModule` gets the same behavior from `TSocketServerModule::serve()` (pradosoft/prado#1419).
- `TWebSocketModule` serves on its `EventLoop`, the `IEventLoop` that `TSocketServerModule` now owns. The module's `EventLoopClass` defaults to `TSocketReactor`, and `setEventLoop()`/`setEventLoopClass()` accept only a `TSocketReactor`, because the server ticks its loop. `createReactor()` stays the module's seam for building the reactor.
- In-process durations run on PRADO's monotonic clock (`TMonotonicClockAwareTrait`): the connection's `drainClose()` deadline, the HTTP/1.1 handshake deadline, the Redis heartbeat, prune and reconnect throttles, the File presence refresh, and the mesh heartbeat, scan, re-dial and re-announce intervals, dial and challenge deadlines and node liveness. Timestamps other processes compare (File modification times) stay on the wall `Clock`. `TWebSocketHandshake::readHandshake()`, `receiveRequest()` and the `clock` option of `acceptConnection()`/`openConnection()` accept a `TMonotonicClock` as well as an `IClock`, and measure on a monotonic clock by default; after a deadline-bounded read the stream's read timeout returns to `default_socket_timeout`.
- `TWebSocketConnection::drainClose()` on a blocking stream whose peer stays silent returns false at the timeout; before, the read-timeout exception made it report true.
- `TWebSocketServer` re-arms a transport for writability only when its write state changes, and flushes HTTP/2 output from HTTP/2 sessions only, so idle sessions cost less per tick.
- `TRedisBackplane::DRAIN_LIMIT` (1000) is the batch read per round trip; `DrainLimit` caps a whole tick.
- The permessage-deflate extension documents its `BFINAL` strictness: a message must end with the empty block header that remains after the sync-flush trailer is stripped.
- `prado-pubsub.js`: the client is open when the `welcome` arrives, and its `open` listeners run before the channels are re-subscribed and the held requests sent; each request frame carries its `id` first; 1007 and 1009 are no longer fatal (`fatalCloseCodes` defaults to 1002, 1003, 1008, 1010, 4401 and 4403), and the request that caused the close fails with `disconnected`.
- A pub/sub `ping` with an `id` is answered with `ack`; one without is answered with `pong`. Requests decode with `JSON_BIGINT_AS_STRING`. `MAX_ID_LENGTH` (64) is documented in bytes, as it is checked. `dispatchRequest()`, `requestPublish()` and `requestSend()` take the frame's JSON text as an optional last parameter.
- `examples/chat`: `chat.join` returns a `token`, and the page subscribes to its room after joining.

### Upgrading
- Run on PHP 8.2 or later. PHP 8.1 is no longer supported: PRADO 4.4 does not install on it.
- Requires PRADO 4.4 master with the event loop API (pradosoft/prado#1377, #1419). Code that schedules on `TWebSocketServer::getReactor()` uses `delay()`, `repeat()` and `cancel()` in place of `after()`/`scheduleAt()`, `every()` and `cancelTimer()`. Callbacks given to `register()` are called as `(string $callbackId, IResource $source)`.
- Requires PRADO master with the monotonic clock (pradosoft/prado#1440). `TWebSocketServer::setClock()` no longer moves the server's timeouts; a test that advanced them through a `TMockClock` sets a `TMonotonicClock` subclass with `$server->setMonotonicClock($clock)` instead, before the reactor is created.
- A `TWebSocketModule` subclass that overrides `createReactor()` keeps working. Setting the module's `EventLoopClass` or `EventLoop` to a non-reactor loop such as `TRevoltEventLoop` throws.
- `serve()` can return up to `ShutdownTimeout` (2 s) later, while live WebSockets complete their close handshake; set it to 0 to end them as soon as their Close is written. An exception from a reactor callback no longer propagates out of `serve()`; to keep that, set a reactor `ErrorHandler` that rethrows, or override `handleLoopError()`.
- An upgrade request with `Transfer-Encoding`, a non-zero `Content-Length`, a repeated `Host`, or an obs-fold line is refused with 400.
- A client configured with `TPermessageDeflateNegotiator` `serverMaxWindowBits` fails the handshake with a server that does not echo `server_max_window_bits`, including a 1.1.0 server when 15 is offered.
- A subclass that overrides the static `TWebSocketHandshake::readHandshake()` or `receiveRequest()` widens its `$clock` parameter to `IClock|TMonotonicClock|null`. `THttp1WebSocketProtocol::setClock()` no longer moves the handshake deadline; set `setMonotonicClock()`.
- A test that advanced a backplane's heartbeat, reconnect, dial, challenge or liveness timing with `setClock()` and a `TMockClock` sets a `TMonotonicClock` subclass with `setMonotonicClock()` instead.
- Mesh links apply `LinkMaxMessageSize` (default 10 MiB) at both ends rather than the server's `MaxMessageSize`; set it alike on every node, above the client limit by a third for base64.

## [1.1.0] - 2026-09-22

This release resyncs the extension with PRADO 4.4 development HEAD and lands a full audit and hardening pass. It changes some public API; see [Upgrading from 1.0.x](#upgrading-from-10x).

### Added
- `TWebSocketModule` is a `TSocketServerModule`: `prado-cli websocket/serve` (`TWebSocketServerAction`) runs a configured `TWebSocketServer` as a daemon with signal handling and the `socket_server` permission gate. The module configures the server through `ServerClass`, `Handler`/`HandlerClass`, `Subprotocols`, `Origins`, `AllowedHosts`, `PermessageDeflate`, `MaxMessageSize`, `MaxSendBufferBytes`, `HandshakeTimeout`, `IdleTimeout`, `CloseTimeout` and `MaxConnections`, and re-raises the handler's events as `onOpen`, `onMessage`, `onClose` and `onError`.
- `TWebSocketServer` runs on PRADO's `TSocketReactor`: the listener, sessions and cluster sources are reactor sources, writes are armed per transport, and the handshake, close and idle deadlines are reactor timers.
- TLS: `TWebSocketServer::bind('tls://…')` runs each accepted socket's TLS handshake non-blocking under the handshake deadline; ALPN `h2` selects HTTP/2 without a preface (`getIsSecure()`).
- `CloseTimeout` (default 5 s): a closing session drains the server's Close frame and is ended at the deadline.
- `MaxSendBufferBytes` on `TWebSocketServer`, `THttp2WebSocketProtocol` and `TWebSocketModule`, applied to every connection the server creates.
- `TWebSocketServer::getLoad()`, which `MaxConnections` bounds: every session, pending handshake, endpoint link and HTTP/2 stream.
- `TWebSocketMessage`: the handler's `onMessage` event carries one, with `getPayload()`, `getOpcode()`, `getIsText()` and `getIsBinary()`. It converts to its payload when used as a string. `TWebSocketConnection::receiveMessage()` returns one.
- Binary cluster delivery: `publish()`, `broadcast()` and `sendToClient()` on `TWebSocketCluster` and `TWebSocketModule` take a `$binary` flag. `TWebSocketEnvelope` carries any byte string intact (`getIsBinary()`).
- `TRedisBackplane::InboxLimit` (default 10000) and pipelined delivery; `IWebSocketCluster::getLocalPresence()`, which the Redis backplane uses to re-declare presence on reconnect.
- Close codes 1012 to 1014 (`TWebSocketCloseCode::ServiceRestart`, `TryAgainLater`, `BadGateway`).
- `THttp1WebSocketProtocol` and `THttp2WebSocketProtocol` negotiate `Subprotocols` and `Extensions` on every accept path; `THttp1WebSocketProtocol` also takes a `HandshakeTimeout`.
- `TWebSocketHandshake::isSupportedVersion()`; `readHandshake()`, `receiveRequest()`, `acceptConnection()` and `openConnection()` take an optional `IClock`.
- `TPermessageDeflateExtension::ensureLevel()` with `MIN_LEVEL`/`MAX_LEVEL` validation.
- `TWebSocketService` answers a SAPI request it cannot upgrade with 400 (not an upgrade), 426 with `Sec-WebSocket-Version: 13` (wrong version), or 501 (a valid upgrade the SAPI cannot serve), instead of an empty 200.
- Logging through `Prado::log()` for refused upgrades, shed connections, deadlines, idle reaps, TLS failures, swallowed handler errors, peer drops, node reaps and backplane faults.
- Error codes: `websocket_envelope_unencodable`, `websocket_frame_length_not_minimal`, `websocket_close_reason_without_code`, `websocket_close_code_not_sendable`, `websocket_permessage_deflate_level_invalid`, `websocket_backplane_mesh_secret_required`, `websocket_backplane_multiple`, `websocket_module_node_id_immutable`, `websocket_module_server_class_invalid`, `websocket_module_handler_class_invalid`, `websocket_service_not_upgrade`, `websocket_service_version_unsupported`, `websocket_service_sapi_unsupported`.
- `CHANGELOG.md`.

### Changed
- Time is read through PRADO's clock seam (`TApplicationClockAwareTrait`); tests inject `TMockClock`. `TMeshBackplane::now()` is removed.
- `THttp2WebSocketProtocol::shutdown()` closes the HTTP/2 session after raising `onClose` for its live connections, freeing the nghttp2 session at once; a later write on one of its connections fails with `websocket_write_failed`.
- `TMeshBackplane::open()` requires a `Secret` (`websocket_backplane_mesh_secret_required`). The mesh challenge is bound to the answering node's id, and a reflected nonce is refused.
- `TFileBackplane` requires an owner-only spool directory; one readable by group or others is refused.
- `TWebSocketModule::setNodeId()` cannot change the id once the cluster exists, and a second `<backplane>` element is refused.
- `TMeshBackplane::SEEN_CAP` raised from 4096 to 65536.
- The development dependency on `belisoful/prado-http2` is `^1.1`; CI covers PHP 8.1 to 8.5 against PRADO `master`, plus Playwright browser tests and the Autobahn fuzzing suite.

### Fixed
- A client that connected and sent nothing hung the whole server (a blocking `STREAM_PEEK`). The handshake was also read synchronously, one byte per call, inside the select loop. Accepted connections now stay non-blocking: the opening bytes are gathered across reactor ticks, and a handshake deadline drops a silent client.
- Idle reaping did not run on a quiet server; deadlines now bound the reactor wait.
- permessage-deflate: inflate steps are sized to the remaining message budget, so a compression bomb overshoots the limit by at most about one input byte's expansion. A truncated DEFLATE stream fails with 1007. Offers and responses with unknown, duplicated, malformed or out-of-range parameters are declined, and the client side enforces the parameters it offered.
- Frame decoding: non-minimal length encodings and 64-bit length overflow are refused. Reading many frames from one buffer is linear rather than quadratic.
- Handshake: exact version token, 24-character base64 key, `Upgrade` parsed as a token list, case-insensitive `Origin`, URL fragments refused, and repeated header fields combined (RFC 7230 section 3.2.2).
- HTTP/2 (RFC 8441): `:scheme`, `:path`, `:authority` and version 13 are validated, and a refused Extended CONNECT is ended instead of left half-open.
- Session teardown: `onClose`, cluster unregistration and the transport close each run even when an earlier step throws, and `MaxConnections` accounting stays correct.
- The send-buffer limit is checked before a frame is queued, so an oversized send does not allocate the payload twice.
- `TWebSocketFrame::close()` refuses a reason without a code and codes that must not be sent.
- Cluster: the Redis backplane purges a node's stale state on open and resyncs on reconnect; File and Redis reap a crashed node's presence; the mesh drops a dead node's link and re-dials seed peers; binary and non-UTF-8 payloads survive every backplane; one failing client no longer stops delivery to the others.

### Upgrading from 1.0.x
- **`onMessage` event parameter.** Handlers attached to `TWebSocketHandler`'s `onMessage` event receive a `TWebSocketMessage` instead of a string. It converts to its payload when used as a string, so `(string) $param` and string concatenation keep working; code that type-checks for `string` must change. Read the opcode with `$param->getOpcode()` or `getIsBinary()`. `IWebSocketHandler::onMessage($connection, $message, $opcode)` is unchanged.
- **`TWebSocketConnection::getLastOpcode()` is removed.** Use `receiveMessage()`, which returns the payload and opcode together.
- **`TWebSocketModule` now extends `TSocketServerModule`.** It owns and configures the server. An application that built its own `TWebSocketServer` can keep doing so and join the module's cluster with `prepareServer()`, or move the server settings onto the module and run `prado-cli websocket/serve`.
- **Mesh clusters need a `Secret`.** `TMeshBackplane` no longer opens without one.
- **File backplane directories must be owner-only** (for example mode `0700`).
- **Stricter protocol validation.** Peers that send non-minimal frame lengths, malformed permessage-deflate parameters, or a non-token `Upgrade` header are now refused.
- **Messages larger than 16 MiB.** A single outbound frame larger than `MaxSendBufferBytes` (default 16 MiB) is refused. When raising `MaxMessageSize` above that, raise `MaxSendBufferBytes` too, or set it to 0 for unlimited.
- **Subclasses.** Several protected `TWebSocketServer` hooks changed signature or were replaced by the reactor-driven flow (`acceptHttp1Session()`, `acceptHttp2Session()`, `dispatchStream()`, `isHttp2Preface()`), and `serve()` takes an optional per-tick callback. `THttp2WebSocketProtocol::rejectStream()` takes extra headers.

### Known limitations
- HTTP/2 streams count toward `MaxConnections` when their session is accepted; a new stream on an existing session past the cap is not refused.
- `TWebSocketConnection::feedMessages()` discards the already-decoded messages of a read when a later frame in that read is malformed.
- Redis commands are blocking round trips (phpredis has no async API); pipelining bounds them to one per envelope.
- The mesh challenge does not prevent a relay through a third node that holds the secret; use a `tls://` transport on untrusted networks.
