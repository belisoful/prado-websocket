# Changelog

All notable changes to `belisoful/prado-websocket` are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Changed
- Tests: the chat example spec gives a page 20 s to come online, and when one does not, the failure names the page's URL and state, its failed requests, and the WebSocket frames it sent and received. One Firefox run on CI had a second page stay offline for the 5 s the spec allowed.

## [1.2.0] - 2026-11-10

This release adds pub/sub for browsers (the `prado.pubsub.v1` subprotocol, a browser client and a chat example), runs on PRADO 4.4's event loop and monotonic clock, and lands two audits of hardening across the server, the protocol layer, HTTP/2 and the cluster backplanes. It raises two minimums, PHP 8.2 and `belisoful/prado-http2` 1.5 for HTTP/2, and changes some behavior; see [Upgrading from 1.1.0](#upgrading-from-110).

### Added
- Pub/sub messaging for browsers: the `prado.pubsub.v1` subprotocol, served by `TWebSocketPubSubHandler` (`Prado\IO\Socket\WebSocket\PubSub\`). Clients `subscribe`, `unsubscribe`, `publish`, `send` (direct message), `call` (application RPC) and `ping` over JSON text frames, routed through the cluster. The handler raises `onSubscribe`, `onPublish`, `onSend` and `onCall` with a `TWebSocketPubSubEventParameter`; client publish and send are denied unless `AllowClientPublish`/`AllowClientSend` or an event handler allows them, and `setAllowed(false)` denies any of the four. `MaxSubscriptions` (default 64), `MaxFrameSize` (default 65536 bytes; a larger request is refused with `limit` before it is decoded, and the `welcome` announces it as `maxFrame`) and `Heartbeat` (default 25 s) configure it; `publish()`, `sendTo()`, `broadcast()`, `subscribe()` and `encodeMessage()` serve application code. A request is refused with a `TWebSocketPubSubException` reply code.
  - A client is admitted once the `onOpen` handlers have returned with the connection still open. The `welcome` is its first frame and a request that arrives earlier is ignored, so a handler that authenticates with an asynchronous lookup and then closes with 4401 has served nothing. `getClientId()`, `getSubscriptions()`, `subscribe()` and `unsubscribe()` work from `onOpen` on.
  - A publish or send relays the canonical JSON of the request's `data`: no insignificant whitespace, normalized string escapes and number spellings, and of duplicate members the last. Subscribers therefore receive what the event handlers saw. `{}`, objects with numeric keys, member order and the digits of an integer past 64 bits are kept. `TWebSocketPubSubEventParameter::getDataJson()` gives a handler that text, and `setData()` replaces what is relayed. Handlers see `data` and `params` decoded as `json_decode()` does, so an integer past 64 bits is a float. A number outside the float range (`1e400`) is `bad_request`.
  - An `id` is an integer in the signed 64-bit range or a string of 1 to 64 bytes. A frame that cannot be decoded, or is over `MaxFrameSize`, is answered with the `id` that a bounded scan of its top-level members finds, so the client's request settles at once. A `ping` with an `id` is acked; one without is answered with `pong`. A channel name is 1 to 128 of `A-Z a-z 0-9 _ . : / -`, with no trailing newline.
  - An exception that is not a `TWebSocketPubSubException`, a `TWebSocketException` from a write to another client included, is logged and answered `internal`. Only a failed write of the requester's own reply ends its connection.
- `prado-pubsub.js`, the dependency-free browser client (`TWebSocketPubSubHandler::getClientScriptPath()`): promise-based requests with timeouts, reconnection with exponential backoff and jitter, re-subscription (once per channel), an offline queue, and a heartbeat that detects a stalled connection. The client is open when the `welcome` arrives; its `open` listeners run before the channels are re-subscribed and the held requests sent, and each request frame carries its `id` first. A socket that opens and receives no `welcome` within `welcomeTimeout` (default 10 s; 0 disables) is dropped with close code 4001 and retried. Close codes 1002, 1003, 1008, 1010, 4401 and 4403 end reconnection (`fatalCloseCodes`), and `close()` is final, from a `close` listener too. A request over `maxFrame` is rejected with `limit` and one that cannot be serialized with `bad_request`; a subscribe that times out is unsubscribed; a server frame that is not a JSON object is reported as `bad_frame`. In Node the client loads with `require()` (a `package.json` beside it declares `"type": "commonjs"`).
- `IWebSocketClusterAware`. `TWebSocketModule` gives its cluster to a cluster-aware handler and re-raises the pub/sub request events as its own `onSubscribe`, `onPublish`, `onSend` and `onCall`.
- Error codes: `websocket_pubsub_frame_too_large`, `websocket_pubsub_frame_malformed`, `websocket_pubsub_type_unknown`, `websocket_pubsub_channel_invalid`, `websocket_pubsub_field_required`, `websocket_pubsub_subscription_limit`, `websocket_pubsub_forbidden`, `websocket_pubsub_client_unknown`, `websocket_pubsub_method_unknown`, `websocket_pubsub_internal_error`.
- Error codes: `websocket_module_event_loop_invalid`, `websocket_module_event_loop_class_invalid`.
- `IWebSocketBufferedBackplane`: an optional backplane interface (`getWriteSources()`, `flushSource()`) through which the server drains a backplane's queued socket output when the socket becomes writable. `TMeshBackplane` implements it; `IWebSocketBackplane` is unchanged.
- `TPermessageDeflateExtension::isAvailable()` and `TPermessageDeflateNegotiator::isAvailable()` report whether ext-zlib is loaded. Error codes: `websocket_permessage_deflate_zlib_missing`, `websocket_permessage_deflate_deflate_failed`.
- Playwright specs for the browser client against the pub/sub handler (`tests/playwright/pubsub.spec.js`); `ws-server.php` serves pub/sub with `WS_PUBSUB=1`.
- `examples/chat`: a multi-room chat on `TWebSocketPubSubHandler` and `prado-pubsub.js`, with history, whispers and reconnection. It runs as a standalone server or as a PRADO application (`websocket/serve`), from this repository or from an installed copy, and `tests/playwright/chat-example.spec.js` covers both versions. A nickname holds visible characters only and belongs to one client at a time, ignoring case; the `token` that `chat.join` returns takes it back after a reconnect. Whispers are addressed by client id. `?ws=` accepts only a URL on the page's own host, and at most `MAX_ROOMS` rooms keep state.

### Security
- A connection that this side closed delivers nothing more to its handler. Before, a client refused in `onOpen` (closed with 4401, as the pub/sub docs recommend) still had every request it sent until its own Close run: pipelined behind the handshake, or sent after the server's Close. `TWebSocketServer` (HTTP/1.1 and HTTP/2) and the synchronous `handleConnection()` loop stop dispatching once `TWebSocketConnection::getIsCloseInitiator()` is true; messages before a Close the peer sent are still delivered. `TWebSocketPubSubHandler` ignores requests on such a connection too.
- `TMeshBackplane`: the accepting node answers a peer's challenge only after verifying that peer, so the dialer answers first. Before, an attacker without the secret could replay one captured plaintext handshake to two nodes and have each sign the other's nonce, passing both challenges and receiving presence and cluster traffic.
- HTTP/2 is held to the limits HTTP/1.1 has. A transport is a pending handshake while it carries no WebSocket stream, so a peer that sends `PRI ` or only the preface is dropped at `HandshakeTimeout`, and so is one whose last stream has closed and that opens no other; an idle transport is sent an HTTP/2 PING and reaped when it goes unanswered, and one that carries no stream is ended, under `IdleTimeout`; a stream that never completes its close is reset at `CloseTimeout`. Before, an HTTP/2 transport escaped all three.
- `MaxConnections` counts each HTTP/2 stream as it opens: a stream past the limit is refused with 503, and each session advertises SETTINGS_MAX_CONCURRENT_STREAMS, which nghttp2 enforces: one less than the limit (its own transport counts toward the load), and 100 when `MaxConnections` is 0 (`THttp2WebSocketProtocol::setAdmission()`, `setMaxConcurrentStreams()`). Before, one transport could open any number of WebSockets.
- `MaxSendBufferBytes` bounds an HTTP/2 stream: the limit counts the bytes the stream holds while its peer withholds flow-control window (`TWebSocketConnection::getQueuedLength()`), and the server pulls no more HTTP/2 output for a transport holding `HTTP2_OUTPUT_HIGH_WATER` bytes. Before, a peer granting no window let a stream queue without limit.
- A peer that resets while being shed at `MaxConnections` no longer keeps its slot. The 503 write failed and skipped the close, so each such peer raised the load for good until every client was refused.
- A large frame received in small reads costs time linear in its size; each read copied the whole buffered frame, so a peer trickling a frame near `MaxMessageSize` could occupy the event loop. Such a frame is also held in about its own size, the pieces being joined into strings of about 64 KiB as they arrive. Bytes received after the peer's Close are discarded rather than buffered without limit.
- The HTTP/1.1 upgrade parser refuses with 400 a request head with a second `Host`, whitespace before a field's colon, or an obs-fold line, and an upgrade carrying `Transfer-Encoding` or a non-zero `Content-Length`, whose body would otherwise be read as WebSocket frames (RFC 7230 §3.2.4, §5.4). `TWebSocketHandshake::parseHttpMessage()` reports these as `malformed`.
- `TWebSocketHandshake::buildClientRequest()`, `buildServerResponse()` and `buildRejection()` refuse a host, path, key, header name or value, or reason phrase containing CR, LF or NUL (`websocket_http_field_invalid`), so a caller-supplied value cannot inject a header.
- `HandshakeTimeout` bounds a silent peer on a blocking stream: `readHandshake()` gives the stream the time remaining as its read timeout before each read. Before, a peer that sent one line held the synchronous path for `default_socket_timeout` and then escaped `serveConnection()` with a `RuntimeException`.
- An HTTP/2 session holds at most `THttp2WebSocketProtocol::MAX_DEFERRED_BYTES` (1 MiB) of input received while a handler waits on the event loop; a peer that floods control frames past it ends the session. Before, flow control bounded only DATA, so held PING or SETTINGS frames grew without limit.
- An HTTP/2 request's header list is limited to 64 KiB, by `belisoful/prado-http2` 1.4.0 (`TH2Session::DEFAULT_MAX_HEADER_LIST_SIZE`): a larger header block resets its stream and the session carries on. Earlier prado-http2 releases put no limit on the decoded size, so about 147 KB of HPACK on the wire decoded to a 574 MB header value and ended the server process, with every connection it held, before any WebSocket check ran. Composer now refuses to install those releases beside this package.
- `TMeshBackplane`: an accepted peer that has not answered its challenge may send messages of at most `UNVERIFIED_MESSAGE_SIZE` (4096) bytes until it is verified. Before, each of up to `MaxPendingPeers` links held open with a replayed handshake could buffer a full `MaxMessageSize` (about 640 MiB in all).
- `TMeshBackplane::PeerPattern`: a PCRE an announced peer URI must match before a node dials it; seeds are always dialed. The default (`''`) dials any announced `tcp://`, `tls://` or `ssl://` URI, as before. Error code: `websocket_backplane_mesh_peer_pattern_invalid`.
- `TFileBackplane::open()` logs a warning when a parent directory of the spool is owned by another user, or is writable by group or others without the sticky bit.
- An HTTP/2 stream the server has finished with leaves its session and buffers nothing. A refused Extended CONNECT (400, 403, 426, 503) is answered on a HEADERS frame that ends the stream, and a closed or failed WebSocket's stream ends after its Close frame. The stream is then reset (RST_STREAM NO_ERROR, RFC 9113 §8.1) when the client has not ended its side, and the DATA the client sends meanwhile is discarded. A finished stream whose last frame cannot leave, because the client grants no flow-control window, is reset at `CloseTimeout`. Before, such a stream stayed in the session until the client ended it and buffered whatever the client kept sending: 64 MB sent to a refused stream held 61 MiB, and 20,000 refused requests held 20,000 streams, with no authentication needed.
- A protocol error ends reading on a connection. `TWebSocketConnection` drops its read buffer and the message it was reassembling, `feedMessages()` discards later bytes, and `receiveFrame()` returns null without reading (`getIsFailed()`). The server ends an HTTP/1.1 session on such an error once its Close has drained, and resets an HTTP/2 stream, also when this side had sent its Close first (a client refused in `onOpen`); the handler then hears `onClose` and no `onError`.
- A permessage-deflate message may end its DEFLATE stream once. A second `BFINAL` block in one message is refused with 1007 (`websocket_permessage_deflate_inflate_failed`). Before, each `BFINAL` block restarted inflate on a new context, so a frame of empty final blocks cost about a second of CPU per MiB, inflated to nothing and passed `MaxMessageSize`.
- `TWebSocketConnection::drainClose()` ends at its timeout whatever the peer sends: the deadline is checked before every transport read, and a blocking stream gets the time remaining as its read timeout. Before, a peer sending a Ping every 0.2 s, or one frame a byte at a time, held a 1 s drain for as long as it kept sending.
- The synchronous `handleConnection()` loop waits for the peer's Close for at most `CloseTimeout` (default 5 s; `setCloseTimeout()` on `TWebSocketHandler`, `TWebSocketPubSubHandler` and `TWebSocketService`) once the application has closed the connection. Before, a peer that kept sending held the worker.
- The HTTP/1.1 upgrade parser refuses with 400 a request whose method is not exactly `GET` (`get` was accepted) and a head with a line that has no colon or no field name (`parseHttpMessage()` reports it as `malformed`). The client refuses a status line whose status is not exactly three digits (`101abc` was read as 101).
- `TWebSocketModule` refuses a limit or timeout that is not a number of zero or more with a `TConfigurationException`. Before, `MaxMessageSize="abc"`, `"0x10"` or `"true"` became 0 (unlimited), `"10M"` became 10, and a negative was stored; the same held for `MaxSendBufferBytes`, `MaxConnections`, `HandshakeTimeout`, `IdleTimeout` and `CloseTimeout`.

### Fixed
- A mesh peer message larger than the socket buffer no longer waits for the next send on that link: the link flushes on every tick, and the server watches links with queued output for writability. Before, a large broadcast could stall for minutes, and steady traffic overflowed the link and dropped the peer.
- When a node crashes, every node drops its clients, not only the one that reaped it: Redis sends a `NODE_DOWN` (the reserved envelope type, now handled by `TWebSocketCluster`) to every node, and the File backplane logs a presence drop per reaped client.
- A node that restarts under a static `NodeId`, or reconnects to Redis after an outage, replaces its presence on every node, so clients of its previous incarnation and clients that left during the outage no longer linger. The mesh detects a restart from a per-process incarnation in each node announce; nodes running 1.1.0 ignore it, so a rolling upgrade converges once every node is upgraded.
- A Redis node reaped while it was stalled (a GC pause, a suspended VM) rejoins on its next heartbeat, declaring its channel interest and presence again instead of staying unreachable.
- The File backplane's reaper drops the decoded client id, so the clients of a node whose id needs URL encoding (such as `host:q`) are removed; and a File node that stalled past twice `PresenceTtl` writes and announces its live clients again instead of leaving an empty presence file.
- An HTTP/2 session that nghttp2 has finished with, after a peer's connection error (a malformed frame) or a completed GOAWAY, is closed once its GOAWAY is sent. Before, the transport and its streams were held open.
- Socket tests no longer block on a reply the server has not yet sent: they pump the server until the bytes arrive, so a slow tick passes and a real failure fails within seconds. This was the intermittent 60 s failure on PHP 8.5.
- A throwing handler `onClose` on an HTTP/2 stream no longer skips the cluster unregister of that stream, or of the transport's other streams when it ends.
- A handler exception fails only its own connection, as on the synchronous path: `onError` is raised and the WebSocket closes with 1011, or with the exception's close code for a `TWebSocketException`. Before, over HTTP/2 it dropped every WebSocket on the transport without `onError`, and over HTTP/1.1 through `serveOnce()` it dropped the transport with no Close, no `onError`, and lost the rest of the read. A throwing `onOpen` on an HTTP/2 stream resets that stream only.
- `TWebSocketServer::serve()` shuts down gracefully: when it ends, every live WebSocket (HTTP/2 streams included) is sent a Close with 1001 and given `ShutdownTimeout` to answer, then every session ends through `onClose` and the cluster unregister, and every transport is closed. A reactor timer that fires during that wait does not end it. Before, `onClose` never ran on shutdown, and a standalone server leaked the transports.
- An exception from an application timer or a fiber the loop resumes no longer ends `serve()`: it is logged at ERROR and the loop carries on. A reactor that already has an `ErrorHandler` keeps it. `serve()` restores the prior `TAsync` loop and detaches when `cluster->open()` or `cluster->close()` throws.
- A handler that waits on the main fiber no longer has its HTTP/1.1 session's later messages dispatched re-entrantly, out of order, or after its `onClose`: the transport stays unread until the handler returns. During such a wait the cluster is ticked on every reactor tick, so a readable cluster source no longer spins the loop. The hold covers `onOpen` as well: no message reaches the handler before its `onOpen` has returned, and bytes pipelined behind the handshake are fed afterward (`addClientConnection()` included). The server also keeps up its per-tick housekeeping during the wait, at least every `TWebSocketServer::WAIT_HOUSEKEEPING_INTERVAL` (0.05 s): HTTP/2 output is pulled and written, transports with queued output are armed for writes, and close deadlines are stamped.
- A write to or read from a reset peer throws `websocket_write_failed` / `websocket_read_failed` and marks the connection closed under PRADO's error handler too, which raises the EPIPE/ECONNRESET notice as a `TPhpErrorException` that the `\RuntimeException` catches missed; the send queue no longer grows. The server ends an HTTP/2 session on such a write failure, and the handshake fails with a `TWebSocketException`.
- Messages a read completed before a malformed frame are delivered before the connection fails, over HTTP/1.1, HTTP/2 and mesh links. Before, they were discarded with the read.
- `TWebSocketConnection::receive()`/`receiveFrame()` buffer a frame that arrives in pieces and return null until it is complete. Before, a partial frame on a non-blocking stream threw `websocket_frame_incomplete`, losing its bytes and misparsing the rest.
- A blocking read that reaches the stream's read timeout returns null and keeps the connection and any partial frame (`getReadTimedOut()`). The synchronous `handleConnection()` loop pings an idle peer at each timeout and closes it with 1001 when a second timeout passes with no Pong or message, instead of failing it with 1011 after `default_socket_timeout`.
- The server echoes an offered `server_max_window_bits` even when it is 15, as RFC 7692 §7.1.2.1 requires; a strict client failed the handshake. The client fails a response that omits a `server_max_window_bits` it offered.
- `close()` with a reason over 123 bytes, a reason that is not UTF-8, or an unsendable code throws before changing state; before, the connection was left closing with nothing sent. `TWebSocketFrame::close()` checks the reason's length and encoding.
- `isHostAllowed()` (`AllowedHosts`) compares the host without regard to case, as the Origin check does.
- `THttp2WebSocketProtocol::send()` returns, in the same call, the output produced by input held while the session was busy. Input held across a `receive()` that threw is fed before the next call's bytes. The synchronous HTTP/2 `serve()` raises `onClose` for live streams when a transport read or write throws.
- The accepting end of a mesh link no longer inherits the client `MaxMessageSize`, so a binary broadcast near the client limit, larger once base64-encoded in an envelope, no longer drops the peer: both ends apply `TMeshBackplane::LinkMaxMessageSize`. Its default equals the client default, so raise it by a third where clients send binary messages near their limit.
- A `tls://` or `ssl://` mesh dial no longer blocks the event loop: the node connects over TCP asynchronously and runs the TLS handshake without blocking, under `Timeout`, with the URI's host as the peer name. A dial that is still connecting is one of `getWriteSources()`, so writability completes it instead of the next cluster tick. A hostname is resolved by a short child process running the system resolver, whose output the loop polls under `Timeout`; the address is cached for `RESOLVE_TTL` (60 s) and dropped when a dial to it fails. At most `MAX_RESOLVERS` (8) lookups run at once and the rest queue; a lookup is killed at `Timeout` and when the backplane closes, which waits at most `RESOLVER_REAP_TIME` (1 s) for the children. The child is `ResolverBinary`: the running PHP CLI, or `php` in PHP's binary directory under php-fpm or php-cgi. A name with no IPv4 address is resolved for IPv6 through the system resolver, then by its `AAAA` records. A name may contain underscores, and an IPv6 address with a zone (`[fe80::1%eth0]`) is dialed as written. Before, `stream_socket_client()` resolved the hostname inside the loop on every dial and re-dial.
- Mesh presence converges after a transient silence in a partial mesh: a node that hears from a node it holds no liveness for floods a `NODE_SYNC` naming it, and that node re-announces its presence, at most once per `ANNOUNCE_INTERVAL` (1 s). Before, the clients of a node behind an intermediary were lost for good. Nodes running 1.1.0 relay the request and do not answer it.
- The Redis inbox drain reads and trims in one `MULTI` transaction, and a reap is one `WATCH`ed transaction covering the registry, channel interest, inbox, presence and the `NODE_DOWN` to every node; a heartbeat writes its key before rejoining the registry. A node that resumes during a peer's reap now either aborts the reap or rejoins after it, and a producer's trim can no longer delete unread entries. Each inbox push sets the inbox to expire after three `NodeTtl`, so an inbox recreated after a reap is removed.
- Redis and File read inbound traffic in bounded ticks (`DrainLimit`) and report a backlog, and the server ticks the cluster again at once, whatever tick timeout its caller passed (`TWebSocketModule` serves with one second). A disconnected or closed backplane reports no backlog. Before, Redis drained at most 1000 envelopes per poll, about one per second when idle, and sustained churn filled the inbox to `InboxLimit`, whose trim discards the oldest entries, presence drops included.
- A File node no longer reaps its own live clients' presence files after a stall longer than twice `PresenceTtl`, when the refresh `touch()` left a stale cached mtime.
- `TWebSocketCluster::unregister()` visits only the disconnecting client's channels; before, every disconnect scanned every channel on the node. `sendToClient()` sends nothing to a client the presence mirror does not hold.
- `TWebSocketEnvelope::decode()` requires the type and the origin to be strings and the type to be a well-formed name (an unknown well-formed type is still relayed). An envelope without an id gets one derived from its bytes, so copies relayed over several paths are recognized as duplicates.
- Docblocks: `IWebSocketBackplane` and `TNullBackplane` no longer call the Redis backplane "pub/sub", and the coordinator, not the backplane, adds the node id to presence metadata.
- A mesh link that drops and returns within `NodeTtl` no longer loses the presence changes made meanwhile. When a link is verified each end floods its full presence under a new generation, and the closing announce drops the clients that generation did not set; the link is also asked for the nodes heard and not linked (`NODE_SYNC`), which flood theirs. Before, a client that left during the gap stayed in the other nodes' mirrors for good, and one that joined behind an intermediary was never learned. Nodes running 1.1.0 ignore the generation, so a mixed mesh converges once every node is upgraded.
- A Redis node that rejoins after being reaped, or reconnects after an outage, replaces its mirror of the other nodes' clients with the presence hash. Before, a remote client that left meanwhile stayed in its mirror, since the reap deleted the inbox that held the drop.
- Two mesh nodes keep one link. A URI announced by a node already linked is another name of that link and is not dialed, so a seed written `tcp://localhost:P` whose node advertises `tcp://127.0.0.1:P` is linked once; of two verified links to one node, the node that dialed the surplus one closes it. Before, such a pair was linked twice and all traffic was sent twice.
- Presence metadata that cannot be JSON-encoded (a non-finite float) is refused to the caller of `TWebSocketCluster::register()` before anything is sent or stored. Before, every mesh link dropped on each re-dial, and Redis disconnected and failed every reconnect. Metadata that is not valid UTF-8 is stored with the bytes substituted, as an envelope carries it; before, the Redis hash and the File presence file stored an empty value.
- `TFileBackplane` lists its presence directory instead of globbing it: a spool path containing `[` seeded and reaped nothing, and a presence file whose name starts with a dot was skipped.
- A `NODE_UP` whose `uri` is not a string no longer makes the mesh `tick()` throw.
- After a handler exception the server waits for the peer's Close, within `CloseTimeout`, before it ends the connection: over HTTP/1.1 through the event loop, on an HTTP/2 stream, and in the synchronous `handleConnection()` loop. The close handshake therefore completes, and a browser reports the 1011 close as clean. Before, the server ended the connection as soon as its own Close was sent, which Firefox, and Chromium over HTTP/1.1, reported with `wasClean` false. A protocol error still ends the connection once its Close is sent, since the connection reads nothing more.
- An HTTP/2 stream that the client ends (END_STREAM) without a WebSocket Close frame is closed: `onClose` is raised and the stream no longer counts toward the load. Before, its connection stayed registered until the transport ended.
- A throwing `onAccept` event handler no longer leaks the accepted transport and its `MaxConnections` slot: the transport is closed and the failure logged.
- `TWebSocketModule` `Subprotocols`, `Origins` and `AllowedHosts` keep each item as a trimmed string and drop empty items. Before, `Subprotocols="v1, 2"` offered the integer 2, which never negotiated, and `Origins="https://app.example, null"` stored `NULL` instead of the opaque origin `null`.
- `serveConnection()` logs a `TWebSocketException` thrown by a handler's `onOpen` or `onClose` as a dispatch failure, at WARNING. Before, it was logged as "Upgrade refused".
- `TWebSocketConnection::flushOutbound()` keeps a send offset and compacts the queue once the written prefix passes half of it. Before, every partial write copied the whole backlog: a peer taking 4 KiB per writable event against a 16 MiB backlog cost about 4 s inside `flushOutbound()`, now 0.02 s.
- A send refused with `websocket_send_buffer_overflow` no longer corrupts permessage-deflate. A full send buffer refuses the message before it is compressed; a message refused once its compressed size is known restarts the sender's DEFLATE stream (`TPermessageDeflateExtension::resetDeflateContext()`). Before, the context kept the unsent message as history and the next message failed at the peer with 1007.
- `TWebSocketConnection::drainClose()` throws the `TInvalidDataValueException` of an unsendable code or an invalid reason. Before, `drainClose(1005)` returned true with nothing sent and the connection marked closed.
- `TWebSocketHandshake::negotiateSubprotocol()` negotiates the subprotocol token `0`, which `array_filter()` dropped.
- Docblocks: `TWebSocketModule`, `TWebSocketServerAction` and `TWebSocketPubSubHandler` name `vendor/bin/prado-cli websocket/serve`, the `--name=value` option form, and a static callable for an event attribute (the dotted `Application.Chat.onMessage` form throws at module load); `THttp2WebSocketProtocol` and `TWebSocketConnection::setValidateMasking()` say that RFC 8441 keeps RFC 6455 framing and that only the receive check on the mask bit is relaxed; `connectPeer()` describes the lookup and lists what it throws; the `PeerPattern` example is anchored at both ends. Every file header links this repository.
- Tests: socket tests that pumped once and then asserted now pump until the state they assert; the HTTP/2 deadline tests run on a test clock; the feed performance tests compare against a baseline measured in the same run and shrink under a coverage driver, so a path-coverage run finishes; `TWebSocketServiceTest` unregisters the application it creates; the mesh resolver tests wait on the child's output and hold their listeners; the Playwright harness waits for each server's own ready line, so a stale server on a fixed port is not tested in place of the new one; the deflate spec asserts `ws.extensions` and compares several messages.
- `ErrorMessagesFileTest` sees an error code chosen by a ternary, counts a code as used only where an exception constructor names it, and checks that each constructor passes one argument per placeholder of its message.

Callbacks given to `register()` are called as `(string $callbackId, IResource $source)`.

An exception from a reactor callback no longer propagates out of `serve()`; to keep that, set a reactor `ErrorHandler` that rethrows, or override `handleLoopError()`.

- Mesh links apply `LinkMaxMessageSize` (default 10 MiB) at both ends rather than the server's `MaxMessageSize`; set it alike on every node, above the client limit by a third for base64.
- **HTTP/2 stream limit.** A session carries at most 100 WebSocket streams when `MaxConnections` is 0, and `MaxConnections` − 1 otherwise. A conforming client queues further streams; nghttp2 refuses those of a client that does not. A caller of `THttp2WebSocketProtocol` that needs another limit passes it to `setMaxConcurrentStreams()`.
- **HTTP/2 stream end.** A client may receive RST_STREAM NO_ERROR after the server's END_STREAM. A client that echoes a Close after the server failed its stream finds the stream reset and cannot write the echo. An HTTP/2 transport is closed `HandshakeTimeout` after its last WebSocket stream closed; a client that keeps a connection open between WebSockets for longer reconnects, and `HandshakeTimeout` 0 turns the deadline off.

- **`MaxConnections` counts HTTP/2 streams.** A deployment sized by transports alone raises the limit by the streams it expects.
- **A connection this side closed delivers nothing more to its handler**, and after a `TWebSocketException` from `feedMessages()`, `feed()`, `receiveFrame()`, `receiveMessage()` or `receive()` the connection reads nothing more. Send the Close the exception names and end the transport; code that caught a message-level error and kept reading no longer receives the frames behind it.
- **`receive()` returns null at a blocking stream's read timeout**, with the connection open and `getReadTimedOut()` true. A loop written `while (($m = $c->receive()) !== null)` now ends there; test `getIsClosed()` to tell the two apart.
- **A handler exception** no longer ends its connection at once: `onError` is raised and the Close sent as before, and `onClose` follows when the peer answers or `CloseTimeout` passes. `TWebSocketServer::failHttp1Session()` takes a fourth parameter, `$awaitPeerClose` (default false); a subclass that overrides it adds the parameter.
- **`drainClose()`** returns false at its timeout when the peer stayed silent, and throws `TInvalidDataValueException` for a code or reason `close()` refuses.
- **`handleConnection()`** waits up to `CloseTimeout` (5 s) for the peer's Close after the application closes, on a non-blocking stream too, where it returned at once before. A class that uses `TWebSocketHandlerTrait` and defines its own `getCloseTimeout()`, `setCloseTimeout()` or `$_closeTimeout` renames it.
- **permessage-deflate** needs ext-zlib when the negotiator or the extension is constructed, not at the first compressed message. An `IWebSocketExtension` whose output depends on earlier messages is not restarted after a send refused with `websocket_send_buffer_overflow`; end the connection on that refusal.
- **`TWebSocketModule` numeric properties are validated.** `MaxMessageSize`, `MaxSendBufferBytes` and `MaxConnections` take a whole number of zero or more; `HandshakeTimeout`, `IdleTimeout`, `CloseTimeout` and `ShutdownTimeout` take a number of zero or more. Anything else throws `TConfigurationException` when the property is set. An empty value still selects the server default. Check configurations for unit suffixes (`"10M"`), fractions on the integer properties, and negatives.
- **`TWebSocketModule` list properties are comma-separated strings.** `Subprotocols`, `Origins` and `AllowedHosts` are split on commas and every item stays a string; a list in parentheses, `(a, b)`, is still accepted. The other `TPropertyValue::ensureArray()` forms (`[a, b]`, `key=>value`) are no longer evaluated.
- **A session's input waits for `onOpen`.** A handler whose `onOpen` waits on the main fiber for a message from the same connection receives it only after `onOpen` returns; start the wait in a fiber with `TAsync::run()` and return. A subclass that overrides `TWebSocketServer::afterTick()` is also called while a handler waits on the main fiber.
- **`serveOnce($seconds)` returns without waiting while the cluster has a backlog.** An `IWebSocketPolledBackplane` reports no backlog when it cannot make progress. `TRedisBackplane::DRAIN_LIMIT` (1000) is now the batch read per round trip; the `DrainLimit` property caps a whole tick.
- **Cluster.** `TWebSocketCluster::register()` throws a `TWebSocketException` (`websocket_envelope_unencodable`) when the presence metadata cannot be JSON-encoded, and does not register the connection. A mesh of 1.1.0 and 1.2.0 nodes works, but a 1.1.0 node adds what a full presence carries and removes nothing, so a link flap is healed only between upgraded nodes. Under php-fpm or php-cgi, set the mesh `ResolverBinary` to a PHP CLI binary if peers are given by hostname and no `php` lies in PHP's binary directory.

## [1.1.0] - 2026-09-22

This release resyncs the extension with PRADO 4.4 development HEAD and lands a full audit and hardening pass. It changes some public API; see [Upgrading from 1.0.x](#upgrading-from-10x).

### Added
- `TWebSocketModule` is a `TSocketServerModule`: `prado-cli websocket/serve` (`TWebSocketServerAction`) runs a configured `TWebSocketServer` as a daemon with signal handling and the `socket_server` permission gate. The module configures the server through `ServerClass`, `Handler`/`HandlerClass`, `Subprotocols`, `Origins`, `AllowedHosts`, `PermessageDeflate`, `MaxMessageSize`, `MaxSendBufferBytes`, `HandshakeTimeout`, `IdleTimeout`, `CloseTimeout` and `MaxConnections`, and re-raises the handler's events as `onOpen`, `onMessage`, `onClose` and `onError`.
- `TWebSocketServer` runs on PRADO's `TSocketReactor`: the listener, sessions and cluster sources are reactor sources, writes are armed per transport, and the handshake, close and idle deadlines are reactor timers.
- TLS: `TWebSocketServer::bind('tls://…')` runs each accepted socket's TLS handshake non-blocking under the handshake deadline; ALPN `h2` selects HTTP/2 without a preface (`getIsSecure()`).
- `CloseTimeout` (default 5 s): a closing session drains the server's Close frame and is ended at the deadline.
- `MaxSendBufferBytes` on `TWebSocketServer`, `THttp2WebSocketProtocol` and `TWebSocketModule`, applied to every connection the server creates.
- `TWebSocketServer::getLoad()`, which `MaxConnections` bounds: every session, pending handshake, endpoint link and HTTP/2 stream.
- `TWebSocketMessage`: the handler's `onMessage` event carries one, with `getPayload()`, `getOpcode()`, `getIsText()` and `getIsBinary()`. It converts to its payload when used as a string. `TWebSocketConnection::receiveMessage()` returns one.
- Binary cluster delivery: `publish()`, `broadcast()` and `sendToClient()` on `TWebSocketCluster` and `TWebSocketModule` take a `$binary` flag. `TWebSocketEnvelope` carries any byte string intact (`getIsBinary()`).
- `TRedisBackplane::InboxLimit` (default 10000) and pipelined delivery; `IWebSocketCluster::getLocalPresence()`, which the Redis backplane uses to re-declare presence on reconnect.
- Close codes 1012 to 1014 (`TWebSocketCloseCode::ServiceRestart`, `TryAgainLater`, `BadGateway`).
- `THttp1WebSocketProtocol` and `THttp2WebSocketProtocol` negotiate `Subprotocols` and `Extensions` on every accept path; `THttp1WebSocketProtocol` also takes a `HandshakeTimeout`.
- `TWebSocketHandshake::isSupportedVersion()`; `readHandshake()`, `receiveRequest()`, `acceptConnection()` and `openConnection()` take an optional `IClock`.
- `TPermessageDeflateExtension::ensureLevel()` with `MIN_LEVEL`/`MAX_LEVEL` validation.
- `TWebSocketService` answers a SAPI request it cannot upgrade with 400 (not an upgrade), 426 with `Sec-WebSocket-Version: 13` (wrong version), or 501 (a valid upgrade the SAPI cannot serve), instead of an empty 200.
- Logging through `Prado::log()` for refused upgrades, shed connections, deadlines, idle reaps, TLS failures, swallowed handler errors, peer drops, node reaps and backplane faults.
- Error codes: `websocket_envelope_unencodable`, `websocket_frame_length_not_minimal`, `websocket_close_reason_without_code`, `websocket_close_code_not_sendable`, `websocket_permessage_deflate_level_invalid`, `websocket_backplane_mesh_secret_required`, `websocket_backplane_multiple`, `websocket_module_node_id_immutable`, `websocket_module_server_class_invalid`, `websocket_module_handler_class_invalid`, `websocket_service_not_upgrade`, `websocket_service_version_unsupported`, `websocket_service_sapi_unsupported`.
- `CHANGELOG.md`.

### Changed
- Time is read through PRADO's clock seam (`TApplicationClockAwareTrait`); tests inject `TMockClock`. `TMeshBackplane::now()` is removed.
- `THttp2WebSocketProtocol::shutdown()` closes the HTTP/2 session after raising `onClose` for its live connections, freeing the nghttp2 session at once; a later write on one of its connections fails with `websocket_write_failed`.
- `TMeshBackplane::open()` requires a `Secret` (`websocket_backplane_mesh_secret_required`). The mesh challenge is bound to the answering node's id, and a reflected nonce is refused.
- `TFileBackplane` requires an owner-only spool directory; one readable by group or others is refused.
- `TWebSocketModule::setNodeId()` cannot change the id once the cluster exists, and a second `<backplane>` element is refused.
- `TMeshBackplane::SEEN_CAP` raised from 4096 to 65536.
- The development dependency on `belisoful/prado-http2` is `^1.1`; CI covers PHP 8.1 to 8.5 against PRADO `master`, plus Playwright browser tests and the Autobahn fuzzing suite.

### Fixed
- A client that connected and sent nothing hung the whole server (a blocking `STREAM_PEEK`). The handshake was also read synchronously, one byte per call, inside the select loop. Accepted connections now stay non-blocking: the opening bytes are gathered across reactor ticks, and a handshake deadline drops a silent client.
- Idle reaping did not run on a quiet server; deadlines now bound the reactor wait.
- permessage-deflate: inflate steps are sized to the remaining message budget, so a compression bomb overshoots the limit by at most about one input byte's expansion. A truncated DEFLATE stream fails with 1007. Offers and responses with unknown, duplicated, malformed or out-of-range parameters are declined, and the client side enforces the parameters it offered.
- Frame decoding: non-minimal length encodings and 64-bit length overflow are refused. Reading many frames from one buffer is linear rather than quadratic.
- Handshake: exact version token, 24-character base64 key, `Upgrade` parsed as a token list, case-insensitive `Origin`, URL fragments refused, and repeated header fields combined (RFC 7230 section 3.2.2).
- HTTP/2 (RFC 8441): `:scheme`, `:path`, `:authority` and version 13 are validated, and a refused Extended CONNECT is ended instead of left half-open.
- Session teardown: `onClose`, cluster unregistration and the transport close each run even when an earlier step throws, and `MaxConnections` accounting stays correct.
- The send-buffer limit is checked before a frame is queued, so an oversized send does not allocate the payload twice.
- `TWebSocketFrame::close()` refuses a reason without a code and codes that must not be sent.
- Cluster: the Redis backplane purges a node's stale state on open and resyncs on reconnect; File and Redis reap a crashed node's presence; the mesh drops a dead node's link and re-dials seed peers; binary and non-UTF-8 payloads survive every backplane; one failing client no longer stops delivery to the others.

### Upgrading from 1.0.x
- **`onMessage` event parameter.** Handlers attached to `TWebSocketHandler`'s `onMessage` event receive a `TWebSocketMessage` instead of a string. It converts to its payload when used as a string, so `(string) $param` and string concatenation keep working; code that type-checks for `string` must change. Read the opcode with `$param->getOpcode()` or `getIsBinary()`. `IWebSocketHandler::onMessage($connection, $message, $opcode)` is unchanged.
- **`TWebSocketConnection::getLastOpcode()` is removed.** Use `receiveMessage()`, which returns the payload and opcode together.
- **`TWebSocketModule` now extends `TSocketServerModule`.** It owns and configures the server. An application that built its own `TWebSocketServer` can keep doing so and join the module's cluster with `prepareServer()`, or move the server settings onto the module and run `prado-cli websocket/serve`.
- **Mesh clusters need a `Secret`.** `TMeshBackplane` no longer opens without one.
- **File backplane directories must be owner-only** (for example mode `0700`).
- **Stricter protocol validation.** Peers that send non-minimal frame lengths, malformed permessage-deflate parameters, or a non-token `Upgrade` header are now refused.
- **Messages larger than 16 MiB.** A single outbound frame larger than `MaxSendBufferBytes` (default 16 MiB) is refused. When raising `MaxMessageSize` above that, raise `MaxSendBufferBytes` too, or set it to 0 for unlimited.
- **Subclasses.** Several protected `TWebSocketServer` hooks changed signature or were replaced by the reactor-driven flow (`acceptHttp1Session()`, `acceptHttp2Session()`, `dispatchStream()`, `isHttp2Preface()`), and `serve()` takes an optional per-tick callback. `THttp2WebSocketProtocol::rejectStream()` takes extra headers.

### Known limitations
- HTTP/2 streams count toward `MaxConnections` when their session is accepted; a new stream on an existing session past the cap is not refused.
- `TWebSocketConnection::feedMessages()` discards the already-decoded messages of a read when a later frame in that read is malformed.
- Redis commands are blocking round trips (phpredis has no async API); pipelining bounds them to one per envelope.
- The mesh challenge does not prevent a relay through a third node that holds the secret; use a `tls://` transport on untrusted networks.
