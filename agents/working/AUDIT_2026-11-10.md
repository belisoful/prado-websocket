# Audit — 2026-11-10

Scope: the whole repository at `ffbb386` plus the uncommitted prado-http2 1.4 accounting (§2):
source, unit and functional tests, line/branch/path coverage, documentation, CI and packaging.
Built against PRADO master `ba2fc3752` and `belisoful/prado-http2` v1.4.0 (`82fcaa9`); the
untagged prado-http2 head `6c1e260` was also run (§2).

Method: six parallel reviews (server and runtime, protocol layer, cluster, pub/sub with the JS
client and chat example, test suites, docs/CI/packaging) plus a review of the HTTP/2 adapter
against prado-http2 1.4.0. Every finding marked *Reproduced* was reproduced by a script and
re-run a second time before it was written down; *Read* means confirmed by reading only. The test
review mutated a scratch copy of `src/` to see which checks no test notices. The previous audit is
`AUDIT_2026-11-03.md`; §9 records which of its fixes hold.

The findings were fixed the same day; §1b records what was done and what is left.

## 3. High

### H1. An HTTP/2 stream the server has finished with is never reclaimed and buffers without limit
*Reproduced.* `THttp2WebSocketProtocol.php:563-566` (`pumpStream`), `:625-629` (`rejectStream`),
`:636-646` (`closeStream`), `:653-660` (`endLocalStream`).
`rejectStream()` and `closeStream()` end only the server's half (`markLocalClosed()`). Until the
client ends its half the stream stays in the nghttp2 session and its `TH2Stream`, and
`pumpStream()` returns without reading when the stream has no connection, so nghttp2's automatic
window updates let the client send for ever into a buffer nobody reads.
- A refused Extended CONNECT (403 for a foreign origin, 400, 426, 503) followed by DATA: 64 MB
  sent, 61 MiB held. The same after a failed WebSocket.
- 20,000 refused requests the client never ended: 20,000 streams held, about 1 KB each, none
  counted by `MaxConnections`. With the default `MaxConnections=0` no
  `SETTINGS_MAX_CONCURRENT_STREAMS` is advertised, so the count is unbounded.
No authentication is needed; an origin the server refuses is enough.
Fix: discard DATA for a stream with no connection; reset a finished stream once its END_STREAM is
sent (RFC 9113 §8.1, `RST_STREAM NO_ERROR`; prado-http2 1.5 `setResetAfterEnd()`); reset one whose
output cannot drain at `CloseTimeout`; always advertise a stream limit. prado-http2 `6c1e260`
provides all of it but the timeout (§2).

### H2. A protocol error on a connection this side closed is swallowed, and its buffer grows
*Reproduced (HTTP/1.1); Read (HTTP/2).* `TWebSocketServer.php:2070`,
`THttp2WebSocketProtocol.php:581`, `TWebSocketConnection.php:730-765`.
The 11-05 fix for H1/M11 skips the failure when `getIsCloseInitiator()` is true. Nothing sets
`discard`, and `feedMessages()` leaves the malformed frame at the head of `_readBuffer`, so every
later read throws again and appends. Scenario: the handler refuses in `onOpen` with `close(4401)`
(the documented pattern); the peer sends `\x83\x00`, then floods. Measured: 23 MiB sent in 3 s,
22 MiB held (twice the default `MaxMessageSize`), no `onError`, and the loop spent 2.98 s of 3.00 s
on that one peer. Bounded by `CloseTimeout` (5 s) per connection and repeatable; unbounded with
`CloseTimeout=0`. Fix: on a protocol exception clear the buffer and mark the connection failed so
later feeds return `[]`; the server sets `discard` or ends the session whoever initiated the close.

### H3. A frame trickled in tiny reads costs 25 to 64 times its size in memory
*Reproduced.* `TWebSocketConnection.php:712-723` (the 11-03 fix for H8).
Each `feedMessages()` call appends one string to `_readChunks`. A 4 MiB frame fed in 1-byte pieces
holds 128 MiB (4,194,307 entries); 10 MiB holds 256 MiB; over a real socket pair with one read per
byte a 1 MiB frame held 64 MiB. Arriving bytes refresh activity, so `IdleTimeout` does not help.
About two million 1-byte segments, spread over any number of connections, pass a 128 MiB
`memory_limit`. Fix: append to the last chunk while it is under 64 KiB.

### H4. permessage-deflate restarts inflate at every `BFINAL` block
*Reproduced.* `TPermessageDeflateExtension.php:215-230`.
One RSV1 frame whose payload is `\x03\x00` repeated (each a complete empty stream with BFINAL),
then `\x00`, makes the decoder create a new inflate context and a fresh `substr` per two bytes.
65 KiB takes 0.06 s, 262 KiB 0.20 s, 1 MiB 0.68–1.4 s; an ordinary 700 KiB message takes 0.0016 s.
It inflates to 0 bytes, so `MaxMessageSize` never trips and an empty message is delivered. At the
10 MiB default one frame blocks the single-threaded loop for several seconds (extrapolated). Only
with compression enabled. Predates `69c38bd`. Coverage agrees: `decodeMessage()` has 14 of 32
branches never run. Fix: accept at most one BFINAL restart per message (RFC 7692 §7.2.3.4).

### H5. Requests are served while `onOpen` is still authenticating
*Reproduced (HTTP/1.1).* `TWebSocketServer.php:1693`, `:1802`, `:1813-1818` (`activateConnection`);
`PubSub/TWebSocketPubSubHandler.php:185-187`.
The session is registered with the reactor before `onOpen`, and `dispatching` (the M5 input hold)
is set only in `handleHttp1Bytes()`. The pub/sub handler also records the client as admitted before
it raises `onOpen`. When `onOpen` waits on the main fiber (`TAsync::sleep`, an async lookup) the
frames the client sends meanwhile are dispatched re-entrantly. Observed order: `onOpen: auth lookup
starts`, `onSubscribe secret`, `onCall admin.dump`, `onOpen: auth failed, closing 4401`; the refused
client had received `{"type":"ack","id":"2","data":{"rows":"sensitive"}}`. Without the close, a
later frame is delivered before a pipelined earlier one, and a frame split across the handshake
read desynchronises the decoder. A synchronous `onOpen` is not affected; HTTP/2 runs `onOpen`
inside the nghttp2 call and is not affected. Fix: mark the session `dispatching` around
`activateConnection()` and feed `$initial` afterwards; the pub/sub handler admits the client after
`onOpen` returns.

### H6. A mesh link flap shorter than `NodeTtl` loses presence changes for good
*Reproduced.* `Cluster/TMeshBackplane.php:644-650` (`sendJoinState`), `:672-683`, `:945-947`,
`:1107-1124`.
`dropPeer()` keeps the peer's presence; on relink the join state only adds (same incarnation, so no
reset), and `NODE_SYNC` fires only for an origin `_nodeSeen` lacks.
- Two nodes: the link drops, a client of B leaves, the seed is re-dialed. A keeps the departed
  client after 2,000 s of heartbeats and `sendToClient()` returns true.
- Chain A-B-C: B-C flaps while A registers one client and unregisters another. C never learns the
  new one and keeps the old one; B is correct.
A link drops on a reset, on `LinkMaxSendBufferBytes` overflow, or on a malformed frame, so this is
ordinary operation. Fix: make the join state authoritative for the sender's node (the receiver
drops what it holds for that node when the link is verified), and request a sync for the nodes
behind the link.

## 4. Medium

### Server and runtime
- **M1. The backlog re-tick is ignored under the module, and a stale Redis flag spins `serve()`.**
  *Reproduced.* `TWebSocketServer.php:882-887` consults `getHasBacklog()` only when `$seconds` is
  null; `TWebSocketModule.php:288` calls `serve(1, …)`, so a backlog drains one slice per second
  (6 envelopes at `DrainLimit` 2: 4.02 s against 1.01 s). `Cluster/TRedisBackplane.php:233-239`
  clears `_backlog` only while connected, so a fault after a bounded drain leaves it true and the
  standalone `serve()` ticks with a zero timeout for the whole outage (1000 of 1000 ticks). The
  11-05 fix for M17 is incomplete. Fix: zero timeout whenever a backlog exists; clear the flag in
  `disconnect()`.
- **M2. An HTTP/2 transport has no bound once its first stream has opened.** *Reproduced.*
  `TWebSocketServer.php:1745`, `:1775`. The handshake deadline is cleared at `onConnection` and
  never re-armed: one stream opened and refused leaves the transport for good (load 1 an hour
  later with `IdleTimeout=0`, the default). `selectHttp2()` also restarts the deadline, so the
  pre-stream bound is up to twice `HandshakeTimeout`. Fix: re-arm when the last stream closes.
- **M3. `flushOutbound()` copies the whole backlog on every partial write.** *Reproduced.*
  `TWebSocketConnection.php:330`, `:342`. A peer taking 4 KiB per writable event against a 16 MiB
  backlog (the default limit) cost 8.3 s inside `flushOutbound()`; 8 MiB cost 2.0 s. It is also why
  `testSendQueuesWithoutBlockingAndDrainsAsThePeerReads` takes 7.8 s, a third of the suite. Fix:
  keep a send offset and compact past half the buffer.

### Cluster
- **M4. A Redis node that rejoins after being reaped keeps remote clients that left meanwhile.**
  *Reproduced (fake Redis).* `Cluster/TRedisBackplane.php:730-745`. `seedPresence()` only adds, and
  the reap deleted the inbox that held the drops. Fix: on `rejoin()`, replace the mirror's remote
  entries with the hash contents.
- **M5. A connect that fails synchronously after the lookup blacklists a gossiped URI.**
  *Reproduced.* `Cluster/TMeshBackplane.php:1452-1459` with `:812`, `:821`. `connectPeer()` sets
  `_knownUris` again and the catch only logs, so later announces of that URI are ignored (an
  AAAA-only host with no IPv6 route, or EMFILE at that moment). Fix: unset it in that catch.
- **M6. Resolver children: no signal, a blocked shutdown, an inherited listener.** *Reproduced.*
  `Cluster/TMeshBackplane.php:1384`, `:1401-1406`, `:1487-1500`. A child younger than 1 s with no
  output is not signalled; `close()` parks it in `_reaping`, which only `tick()` polls, so
  destroying the backplane blocked 6.04 s in `proc_close`. With `Timeout` under 1 s a timed-out
  child is never signalled. The child inherits every open socket: after the server closed, the
  port could not be rebound until the child exited. Fix: `close()` terminates and reaps every
  resolver with a short bounded wait; a timed-out child is signalled on the next tick.
- **M7. Hostname validation refuses names the system resolver accepts.** *Reproduced.*
  `Cluster/TMeshBackplane.php:1361`. `ws_node1` and compose-style `proj_ws_1` throw
  `websocket_backplane_mesh_host_invalid`; before `ffbb386` they resolved. Scoped IPv6 literals
  (`[fe80::1%eth0]`) are refused too. The class docblock promises container service names. Fix:
  allow `_`; add the `D` modifier.

### Pub/sub and the JS client
- **M8. `close()` called inside a `close` listener is undone.** *Reproduced.*
  `PubSub/assets/prado-pubsub.js:257-263`. `_closed()` arms the reconnect timer after emitting
  `close`; a listener that called `ps.close()` is reconnected and re-subscribed 30 ms later, on
