Scope: the whole extension (`src/`, `tests/`, CI, tooling) against PRADO `master` at

## 2. Findings — ranked

Severity: **high** = data loss, security bypass, unbounded resource use, a hang, or a
permanent cluster fault; **medium** = interop or robustness defect reachable by a conforming
or buggy peer; **low** = spec nit, docblock or hygiene. Items marked *confirmed* were
reproduced with a probe script during the audit.

### High

1. **A silent TCP connect hangs the whole server.** *Confirmed.* `TWebSocketServer.php:532-574`:
   `acceptSession()` sets the accepted transport blocking, then `isHttp2Preface()` peeks with
   `stream_socket_recvfrom(..., STREAM_PEEK)`, which does not honor `stream_set_timeout()`
   and never returns until a byte arrives. `nc host port` with no bytes stalls `serveOnce()`
   and every live WebSocket forever. With the peek removed the same probe returns after
   `HandshakeTimeout`.
2. **The accept-path handshake is synchronous inside the select loop.** *Confirmed.*
   `TWebSocketServer.php:531-544` reads the request blocking, one byte per `read(1)`
   (`TWebSocketHandshake.php:512`), so each idle or dribbling connection stalls all traffic
   for up to `HandshakeTimeout` (default 10 s), serialized across connections: 50 silent
   connects hold the loop ~500 s. Fix: keep the transport non-blocking and drive the handshake
   incrementally from a `handshaking` session state with a deadline checked by the reaper.
3. **A quiet server never reaps idle sessions.** `TWebSocketServer.php:388-396`: without a
   cluster `serve()` passes `null` to `select()`, so `reapIdleSessions()` runs only when an
   unrelated socket wakes the loop; a client whose NAT drops silently leaks its fd, session,
   registry and cluster presence indefinitely. `TSocketReactor::resolveTimeout()` in PRADO HEAD
   bounds the wait to the nearest timer; the server duplicates the loop without it.
4. **Inflate output is not bounded per chunk.** `TPermessageDeflateExtension.php:155-166`
   feeds 8 KiB input chunks and checks the running total only after each chunk, but one
   8 KiB chunk can inflate to ~8 MiB (verified: 50 MiB of zeros compresses to 50,974 bytes).
   With `MaxMessageSize = 65536` a 1 KiB frame still materializes ~8 MiB before 1009 fires;
   with the limit at 0 there is no ceiling. Fix: size each input chunk to
   `max(1, ceil(remaining_budget / 1032))` (zlib's maximum ratio) or inflate with a bounded
   output length.
5. **Mesh challenge is reflectable.** `TMeshBackplane.php:377-411, 554-557`: an unverified
   peer may send `AUTH_CHALLENGE(nonce)` where `nonce` is the challenge it just received;
   `answerChallenge()` signs it with the same context `verifyChallenge()` accepts, so the
   peer forwards the answer as its own `AUTH_RESPONSE` and becomes verified. Combined with
   the replayable handshake proof (`:483-491`, no acceptor nonce or expiry) the replay
   defence is bypassed. Fix: bind the answer to the direction (distinct contexts for "my
   challenge" vs "your challenge", or include both node ids), and refuse to answer a nonce
   equal to the one this node issued.
6. **Redis reconnect loses channel interest and outage-time presence.**
   `TRedisBackplane.php:123, 228-239, 313-319`: `open()` clears `_channels`;
   `subscribe()`/`putPresence()` are no-ops while disconnected and nothing is queued; the
   coordinator declares interest only on the first local subscriber, so after any Redis
   restart this node never again receives cross-node publishes for its channels.
7. **Phantom presence after a node crash (Redis and File).** Neither backplane calls
   `IWebSocketCluster::dropNodePresence()` (only the mesh does, `TMeshBackplane.php:238`):
   `TRedisBackplane.php:442-482` `reapNode()` cleans Redis keys only, `TFileBackplane.php:258-269`
   unlinks files only, so running nodes keep a dead node's clients in their mirror forever.
   A Redis node restarting under a static `NodeId` inside `NodeTtl` never purges its own
   previous incarnation's `presence` entries either.
8. **Binary or non-UTF-8 cluster payloads crash the backplane.** `TWebSocketEnvelope.php:175-185`
   `encode()` returns `false` from `json_encode` on invalid UTF-8, which the `: string`
   return turns into a `TypeError`; the mesh catches it and drops the peer, Redis `guard()`
   disconnects, File `append()` throws into the serve loop. `TWebSocketCluster.php:472` also
   relays every envelope as a Text frame, so a valid-UTF-8 binary arrives as text. Fix: a
   binary flag plus base64, or `JSON_THROW_ON_ERROR` with an explicit error code.
9. **Dead mesh links are never dropped, so a rebooted peer is never re-dialed.**
   `TMeshBackplane.php:186-198, 225-238`: a half-open link reads `''` forever (not `null`);
   `detectFailures()` drops presence but leaves the peer and its URI in `_connectedUris`, so
   `connectPeer()` returns early at `:444`. Seeds are dialed once only (`:141-150`) with no
   periodic re-dial.
10. **A throwing local `send()` aborts a whole drained batch.** `TRedisBackplane.php:196-206`
    `guard()` treats any `\Throwable` from `receiveEnvelope()` (including
    `TWebSocketException` from one slow client's send-buffer overflow) as a Redis fault:
    the node disconnects for 5 s and the already `lTrim`med remainder is lost.
    `TWebSocketCluster.php:445-461` `deliverAll()`/`deliverChannel()` have no per-client
    try/catch, and `TFileBackplane.php:227-233` / `TMeshBackplane.php:701-713` advance the
    offset or socket before delivery, so envelopes after the failing one are dropped.

### Medium

11. **Unguarded reaper and `onClose` ordering can end `serve()` or leak.** `TWebSocketServer.php:427`
    calls `reapIdleSessions()` outside every try/catch; `endHttp1Session()` (`:907-913`) runs
    the user `onClose` before `unregister()` and `close()`, so a throwing handler skips the
    cluster unregister (phantom presence), a throwing backplane (Redis down) escapes
    `serveOnce()` and exits the daemon, and `dropSession()` (`:496-510`) can leave the
    transport unclosed.
12. **Server-initiated `close()` never completes on its own.** `TWebSocketConnection.php:344-351`
    only sets `_closing`; the session ends on the peer's Close. The idle reaper
    (`TWebSocketServer.php:462`) still pings a closing connection and a Pong refreshes it, so a
    peer that never answers Close lives forever. Also `:865-873` end the session right after
    the echoed Close is queued, so under backpressure the Close frame never reaches the wire
    (browsers report 1006).
13. **`TWebSocketService::run()` answers an Upgrade request with an empty 200.**
    `TWebSocketService.php:65-70` acts only when `setConnection()` was called and nothing in
    `src/` or the framework calls it, so the README's SAPI entry point (lines 123-131) yields
    a failed handshake with no 426/501, no Origin check and no header validation.
14. **`onMessage` loses the opcode and `getLastOpcode()` is wrong mid-batch.**
    `TWebSocketHandlerTrait.php:70-73` raises `(connection, message)` only; `pumpHttp1Session()`
    (`TWebSocketServer.php:862-871`) fully decodes a read before dispatching, so a handler for
    the first message reads the batch's last opcode. Raise the event with the
    `TWebSocketMessage` (or a `TEventParameter` carrying opcode and payload).
15. **`MaxConnections` counts `_sessions` only.** `TWebSocketServer.php:523`: endpoint and mesh
    peer links (`:593-604`) and HTTP/2 streams are exempt, so a custom `IWebSocketEndpoint`
    with a weak `authenticate()` can be opened without bound.
16. **TLS: HTTP/2 detection reads ciphertext and ALPN is ignored.** `TWebSocketServer.php:568-576`
    peeks raw bytes, so `h2` over `tls://` never matches and falls into HTTP/1.1;
    `TSocketStream::getAlpnProtocol()` exists in PRADO and is never consulted. The mesh dial
    (`TMeshBackplane.php:456`) likewise never calls `stream_socket_enable_crypto` on an async
    `tls://` connect. No `tls://` test exists on either path.
17. **No logging anywhere.** Eight `catch (\Throwable)` blocks in `TWebSocketServer`
    (`:404-410, 415-417, 422-425, 485-487, 507-509, 545-550, 709-722`), two in
    `TWebSocketHandlerTrait` (`:44-48`), and every fault path in the three backplanes swallow
    silently. PRADO HEAD's logger is `Prado\Util\Log\TLogger`; use
    `Prado::log($msg, TLogger::WARNING, static::class)`. A cluster source at EOF plus a
    `tick()` that throws early (`TWebSocketServer.php:393, 421-425`) is a silent 100% CPU loop.
18. **Small-frame read path is O(n²).** *Confirmed.* `TWebSocketConnection.php:448` re-copies
    `_readBuffer` per frame and `TWebSocketFrameCodec.php:228` calls `Prado::createComponent`
    per frame: 64 KiB of 7-byte frames takes 158 ms (0.4 MB/s) against 4.9 ms for one frame.
    Track an offset and compact once per `feedMessages()`.
19. `TWebSocketCloseCode.php:78-81` rejects the IANA-assigned close codes 1012–1014 as protocol
    errors (`isValidIncoming()`), and `isSendable()` refuses them; the docblock at `:73` calls
    1012–2999 "unassigned". A server sending 1012 (Service Restart) is answered with 1002.
20. `TWebSocketHandshake.php:137-138` overwrites repeated header lines; RFC 6455 §11.3 allows
    `Sec-WebSocket-Protocol`/`-Extensions` (and `Connection`) split across lines, so an offered
    subprotocol or `Connection: Upgrade` on a second line is lost.
21. `TPermessageDeflateNegotiator.php:113-141` accepts offers RFC 7692 §7.1 requires declining:
    unknown parameters, duplicate parameters (silently last-wins in `parseExtensionHeader()`,
    `TWebSocketHandshake.php:282`), a value-less `server_max_window_bits`, an out-of-range
    `client_max_window_bits`, and `10x` parsed as 10.
22. `TPermessageDeflateNegotiator.php:170-190` client side ignores its own offered
    `client_no_context_takeover` / `client_max_window_bits` (per §7.1.1.2 the client is bound
    by its offer even when the server does not echo it) and accepts responses that must fail.
    Against a conforming server that trusts the hint this corrupts the stream.
23. **No subprotocol or extension negotiation on three of the four accept paths.**
    `THttp1WebSocketProtocol.php:101-109` `serve()` (used by `serveConnection()`,
    `TWebSocketServer.php:936-950`) calls `acceptConnection()` with no subprotocols, extensions
    or timeout and discards the result; `acceptHttp2Session()` (`:666-669`) and
    `THttp2WebSocketProtocol.php:224-250` pass neither and validate only `:method`/`:protocol`.
    A browser sending `Sec-WebSocket-Protocol: chat` over h2 or the sync path fails its
    handshake; only `acceptHttp1Session()` negotiates.
24. `TPermessageDeflateExtension.php:156-160`: a truncated DEFLATE stream is delivered as a
    complete message (`inflate_add` returns partial output, not `false`).
25. `TWebSocketFrameCodec::readOrNull()` (`:314-324`) and `receiveFrame()` (`:391-393`) treat
    `''` as end-of-stream, but `TStream::read()` returns `''` on EAGAIN too, so `drainClose()`
    and `handleConnection()` on a non-blocking stream misreport the peer as gone.
26. `TMeshBackplane.php:53-54, 329-331, 894-896` docblocks describe an "open mesh" with an
    empty `Secret`, but the code disables the mesh silently; `open()` should throw a
    `TConfigurationException` (new error code) or the docs must change.
27. `TMeshBackplane.php:587-599` binds the first `NODE_UP` seen on a link as the peer's URI
    without checking origin (a relayed heartbeat mis-assigns it when the direct peer has no
    `Advertise`); `:562-577, 359-368` a node reaped by the failure detector and heard again
    never re-sends presence while the link stays up; `:843-849` the `_seen` cap 4096 with
    half-trim re-delivers late duplicates; `TWebSocketCluster.php:67` two nodes with the same
    `NodeId` silently drop each other's traffic.
28. `TRedisBackplane.php:115, 342-354`: every command is a blocking round trip on the serve
    loop (`Timeout` up to 2 s each) and `deliver()` issues one `rPush` per node with no
    pipeline; `:177` inboxes have no length cap.
29. **Design drift from PRADO HEAD's socket layer.** `TWebSocketServer::serveOnce()`
    reimplements select, write arming and time-based reaping that `TSocketReactor` now
    provides (findings 3 and 11 follow from that), and `TWebSocketModule` extends `TModule`
    rather than `TSocketServerModule`, so there is no `prado-cli socket/serve` action, no
    signal handling and no permission gate.

### Low

- `TWebSocketHandshake.php:182` `(int)` version check accepts `13abc`, `13, 8`; `:153-156`
  `base64_decode(..., true)` accepts whitespace in the key; `:155, 488` `Upgrade` is compared
  whole rather than token-split; `:209-216` Origin comparison is case-sensitive and
  `parseUrl()` drops a fragment silently; `:512` one `read(1)` syscall per handshake byte
  (up to 16 K per connection); `:534, 618` `acceptConnection()`/`openConnection()` take no
  timeout.
- `TWebSocketServer.php:534` rounds `HandshakeTimeout` up to whole seconds although
  `TResource::setTimeout()` accepts microseconds; `:586-589` closes a rejected HTTP/1.1
  upgrade without writing the 400/426 that `upgradeError()` computed; `:230-233` the
  send-buffer overflow check runs after the append, so one oversized `send()` allocates the
  payload twice before rejecting.
- `TWebSocketFrameCodec.php:123-130, 187-202` accepts non-minimal length encodings; `:220, 141`
  with `maxPayloadLength = 0` a near-`PHP_INT_MAX` length overflows to float and the read
  buffer grows unbounded; `:284` `applyMask()` allocates a full-length mask string.
- `TWebSocketFrame.php:104-108` `close(null, 'reason')` drops the reason and `pack('n')`
  truncates codes > 65535 with no `isSendable()` guard.
- `TPermessageDeflateExtension.php:236-239, 254-257`: `deflate_init()`/`inflate_init()` never
  return `false` on PHP 8 (they throw `ValueError` on a bad level); `$_level` is unvalidated.
- `TFileBackplane.php:158-166` parent-directory TOCTOU (only the leaf is checked); `:188`
  ownership check silently skipped without `posix`; `:184-186` accepts a 0755 spool although
  the class docblock claims other users cannot read presence; `:163` reports `_directory`
  instead of the failing subpath; `:121, 1005, 1026` `(int)` casts instead of
  `TPropertyValue::ensureInteger()`.
- `TMeshBackplane.php:244-247` connecting dials are added as read sources only, so a dial
  advances only on an unrelated wake-up; `:447-449` any trusted peer can gossip an arbitrary
  `tcp://host:port` that every node will dial (internal port probing); `:759`
  `getResource()` may be null after close.
- `TWebSocketEnvelope.php:104, 211` an empty wire `i` is regenerated per first-hop receiver
  (duplicate delivery on a cycle); `:193-213` `decode()` does not validate `t`.
- `TWebSocketCluster.php:376-385` a peer can overwrite a local client's mirror entry with
  another node; `:77-83` `open()` lacks `@throws`.
- `TWebSocketModule.php:71-74` multiple `<backplane>` elements silently replace each other;
  `:108-114, 138` `setNodeId()` is untyped and ignored after `getCluster()`; `:86-101`
  instantiates a configured backplane class before the `instanceof` check.
- Events are raised with raw values, never `TEventParameter`, so PRADO HEAD's
  `IEventStoppableParameter`/`stopped` cannot veto a message or halt propagation.
- `TWebSocketServer` uses `TApplicationClockAwareTrait` (looks up the application per read);
